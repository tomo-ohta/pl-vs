## 1. いちばん大事なこと（ゲームとしての面白さ）

**先に `docs/game-design.md` を読むこと。** 段階 3 の確認では、「仕掛けがただ部屋にあるだけで、ゲームとして何が面白いのかが検討できていない」とご指摘を受けた。
案の一覧の文字どおりに作るのではなく、1 つずつ「どこが面白いのか」を考えてから作る。

- **扉の向こうの驚き**: 部屋は基本的に扉の向こうにある。扉を開けた瞬間に、**部屋まるごと**がおかしい・部屋まるごとが 1 つの遊びになっている、と分かるようにする。部屋の隅に装置が 1 つあるだけ、にはしない。
- **仕掛け（挑戦）の 4 条件**:
  1. 目標がはっきりしている（向こうの扉へ行く・光を届ける）
  2. 規則が見て分かる（流れ・揺れ・光・音で見せる。説明の文字に頼らない）
  3. 失敗に代償がある（入口へ戻される・最初からやり直す・下へ落ちて階段で戻る）。**体力は減らさない**（体力の規則は後回し）
  4. 普通でない振る舞いに隠しがある（わざと落ちる・流れに逆らう・光から離れる。v2-plan.md 4.7）
- **閉じ込めない**: 最悪の状態（床が崩れた・扉が閉じた・水が満ちた）でも、区画の開口どうしは歩いてつながる。落ちた先・流された先からも必ず戻れる。
- **部屋の形そのものを仕掛けに合わせて作る**（`core/gen/gimmicks/pit.ts`・`maze.ts`・`belts.ts` が手本）。
- **異変（驚き）の 3 条件**: 扉を開けた瞬間に分かる / 中を歩ける・触れられる / 部屋のテーマ（教室・事務所 …）と重なる。
- **案が弱いときは直してよい**: 文字どおりだと面白くない案は、面白くなる形に変える（変えた点は台帳の note に書く）。同じ仕組みの案は 1 つの仕掛けにまとめ、違いを変種（params）にしてよい（台帳では merged）。
- **後回しにしてよいのは**、体力（2.16）・マルチプレイ（2.17）が無いと成り立たない物だけ。非同期マルチプレイの「下地」の案（他人の足跡・置いた物が残る・他人の地図）は、1 人でも遊べる形（作り置きの「誰か」）で作る。
- **将来スマホで遊ぶ**（社内公開）。操作は 移動・視点・跳ぶ・しゃがむ・走る・調べる（E / タップ）・置く/投げる（Q）・懐中電灯（R）だけで遊べること。マウスの細かい操作や、キーボードにしか無い操作を前提にしない。重さもスマホの予算（剛体の数・灯りの数・箱の数）に収める。
- 音は WebAudio の合成（v1 と同じ）。素材は CC0 だけ（CC-BY は不可）。

## 3. ファイルの持ち方（ぶつからないように）

各担当は **自分の git worktree**（別の作業コピー）で作業し、自分のブランチにコミットする。統合（feature/v2-foundation へのマージ）は統合担当が行う。

### 担当だけが書き換えるファイル（`<ws>` は担当名）
- `core/config/tuning/<ws>.ts` … 調整値（数値はすべてここ。キーは `<ws の頭>.<名前>.<数値>`）
- `core/gen/catalog/<ws>.ts` … 案の台帳（書き方は `core/gen/catalog/types.ts`）
- `core/gen/gimmicks/<ws>/` … 仕掛け（`index.ts` に import を足す）
- `core/gen/anomaly/defs/<ws>/` … 部屋まるごとの異変
- `core/sim/parts/<ws>/` … 部品
- `client/views/<ws>/` … 部品の描画（`defineView`）
- `tests/<ws>-*.test.ts` … 試験

### 担当が主に持つ共有ファイル（ほかの担当は、どうしても要るときだけ小さく足す）
| ファイル | 主の担当 |
|---|---|
| `core/sim/player.ts`・`core/sim/collision.ts`・`client/camera/CameraRig.ts`・`core/world/layout.ts` の Zone | move |
| `core/gen/floor/skeleton.ts`・`geometry.ts`・`profile.ts`・`themes.ts` | structure |
| `core/gen/dress/*`（区画の中身） | rooms（oddity も足してよい） |
| `client/audio/*` | sense |
| `client/render/PostFX.ts` | oddity |
| `client/world/Visibility.ts`・`client/world/FloorBuilder.ts` | warp |
| `client/ui/*`・`client/main.ts`・`client/map/*`（新規） | map |
| `client/game/ClientGame.ts`・`core/sim/sim.ts`・`core/sim/part.ts`・`core/gen/floor/index.ts`・`core/gen/floor/gimmicks.ts`・`core/gen/anomaly/index.ts`・`core/gen/secrets/*`・`tests/helpers/*` | 統合担当（各担当は小さく足すだけ） |

共有ファイルを書き換えるときの決まり:
- **足すだけ**にする（既存の行の並べ替え・書き換え・整形をしない。必要な既存の変更は最小に）。
- 足した所は、終わりの報告に全部書く（統合でぶつかったときに直すため）。
- 型の「和」（`ZoneKind`・`GimmickAxis` など）に足すときは、行の末尾に足す。

## 4. 使える仕組み（段階 4 の共通の取り決め）

- **core は純粋な TypeScript**（three・DOM を使わない。`node tools/check-boundaries.mjs`）。決定的に作る（乱数は `core/math/rng.ts` の Rng。`Math.random`・時刻を core で使わない）。import は `.ts` を付ける。Node 26 の型の取り除き（`erasableSyntaxOnly`: enum・名前空間・引数のプロパティは使えない）。
- **仕掛け**: `core/gen/gimmicks/types.ts`（defineGimmick・GimmickContext・SecretOffer）。部品の配線: `core/sim/part.ts`・`core/sim/parts/*`（センサー・論理・動かす物・動き・仕掛けの部品）。
- **異変**: `core/gen/anomaly/types.ts`（pre / post の 2 段・到達の確かめ・取り消し）。**異変は隠しを差し出せない**（隠しは仕掛けを置くときに付く）。隠しの要る異変は、仕掛けとして作る（仕掛けも部屋まるごとを変えてよい）。
- **ゾーン**（`core/world/layout.ts` Zone）: water（遅くなる。`dry` で乾いた玉の海）・friction（滑る）・force（押される）・crawl・hazard・marker・gravity（重さの倍率）。
- **プレイヤー**（段階 4 で足した）: `PlayerState.holding`（持っている物の部品 id。運ぶ担当が使う）・`dropPressed`（Q を押した tick）・`flashlight`（懐中電灯が点いているか。R で切り替え。照らした所だけある床などに使う）。`InputCommand.drop`・`flashlight`。
- **継ぎ目の無い移動**: `PartContext.warp(player, pos, yaw?, seamless = true)`。同じ形の場所の間で、見た目を変えずに位置を移す（速度は向きの差だけ回す）。描画はカメラの補間をずらして飛びを見せない（ClientGame の `player.respawn`・`cause: 'warp'`）。
- **描画**: `client/views/views.ts` の `defineView(type, f)`。`ViewContext` に `audio`（AudioEngine）・`postfx`（PostFX）・`camera`・`scene`・`onEvent(f) → やめる関数`（シミュレーションのイベント）を足した（テストでは無いことがある）。部屋の異変の画面効果は、異変が置く部品の描画から掛ける（部屋に入っている間だけ効く、など）。
- **懐中電灯**: 段階 4 で v2 にもつないだ（R で切り替え。既定は点灯）。
- **見本のフロア**: `?try=id,id`（指定した仕掛け・異変だけ）・`?group=<担当>`（台帳の仕掛け・異変を全部）。G キーで次の場所へ。`?showcase=1/2` は段階 3 の見本のまま。
- **試験の道具**: `tests/helpers/gimmick-lab.ts`（1 部屋だけの実験室。入口・出口の向きと大きさを全部試す）・`tests/helpers/gimmick-rooms.ts`（生成したフロアから、ある仕掛けの部屋を集める）・`tests/helpers/bot.ts`（walkTo: 区画まで歩く人。段差・帯・一方通行の扉に対応）。
- 調整値: `core/config/tuning/<ws>.ts`（spec.ts の num / bool）。既存の `gimmick.chance.*`・`anomaly.share.*`・`floor.roomDoorChance` は変えない（仕掛け・異変・普通の部屋の割合は統合で見る）。

## 5. 合格の条件（全部の案で同じ。プログラムで確かめる）

1. 台帳（`core/gen/catalog/<ws>.ts`）に受け持ちの案が全部ある（`tests/catalog.test.ts`）。実装の id が登録されている。
2. 仕掛け・異変は、ふつうのフロアの生成で出る（重みは控えめに。1 つの仕掛けがフロアを占めない）。`?try=<id>` の見本で置ける。
3. 試験で確かめる:
   - 入口から出口へ通れる（歩く人・決めた入力で）。目標・失敗・やり直しが働く（落ちたら戻れる・流されたら戻れる）
   - 最悪の状態でも閉じ込めない（開口どうしが歩いてつながる）
   - 隠しを差し出すなら、隠しの奥まで行ける（存在型・出現型の両方）
   - 同じ seed で同じフロア（決定的）
4. `npm run verify`（型・境界・全部の試験）が通る。**既存の試験を壊さない**（gen-walk・anomaly-walk などの歩く人の試験も）。
5. 重さ: 1 区画の箱・剛体・灯りが増えすぎない（物理の上限 `gimmick.physicsMax`）。

## 6. 作業の決まり

- 自分の worktree の中だけで作業する。最初に `node_modules` をつなぐ（下）。
- 自分のブランチに、まとまりごとにコミットする（日本語のメッセージ。最後の行に `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`）。**push・main・feature/v2-foundation への操作・マージはしない。**
- git は `export PATH="/Library/Developer/CommandLineTools/usr/bin:$PATH"` を先に付けて使う。
- 撮影画像はコミットしない。ブラウザの画面（ペイン）は使わない（ほかの担当と共有なので）。確認は試験で行い、目で見て確かめたい所は報告に `?try=` の URL として書く（統合担当がまとめて見る）。
- コメント・資料は日本語。まわりのコードと同じ書き方・密度にする。

```bash
WT=$(git rev-parse --show-toplevel)
```
