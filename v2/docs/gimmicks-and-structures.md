# v2 特殊ギミックとフロア構造（案の一覧と実装方式）

2026-10-02 作成。社内の「プロトタイプ置き場」の **THE QUIET ROOMS**（大武さん）と **余白を歩く — BETWEEN SPACES**（村上さん）を調べ、そこにある仕掛けとフロア構造を v2 に取り入れるための資料。案をできるだけ多く挙げ、プロの作り方を調べたうえで、v2 での実装方式を 1 つに絞って提案する。

- 前提: **クリアするまで閉じ込める仕組みは入れない**（ユーザー指示）。仕掛けはどれも「避けて通れる」か「失敗してもすぐ近くからやり直せる」ものにする。
- 印: **[QR]** = THE QUIET ROOMS にある、**[WS]** = 余白を歩くにある、**[v1]** = pro_Liminal v1 にある、印なし = 新しい案。
- 関連: [`v2-plan.md`](v2-plan.md)（**v2 全体計画。決まったことと進め方はこちらが正**）／ [`inheritance-plan.md`](inheritance-plan.md)（v1 からの引き継ぎ方）
- 2026-10-02 の決定: 生成の単位はフロア / 仕掛けはバリエーションの要素で、挑む理由は「隠された場所の発見」（v2-plan.md 4 章）/ プロトタイプはコードも流用してよい / 仕掛けはまとめて導入する / アンケートは入れない

## 1. 調べて分かったこと

### 1.1 THE QUIET ROOMS（フロア生成 + 特殊個室 + ミニゲーム）

**フロアの作り方**
- 基本は **5×5 の区画（ベイ、間隔 8 m）を格子状に並べ、深さ優先探索で迷路状につないだうえで、ループを足す**。区画どうしは廊下でつなぎ、折れ曲がる廊下は L 字にする。
- 床の高さが違う区画は、階段・エスカレーター・坂でつなぐ。天井も傾ける。
- 入口から出口までの道（exitPath）は幅優先探索で求めている。物を置ける場所は、歩ける格子を塗りつぶして（到達判定）決める。
- **空間の型は 16 種**
  - detachedHalls（分棟）/ windingRooms（くねる部屋）/ narrowLow（低く狭い）/ narrowHigh（高く狭い）
  - stairHalls（階段）/ escalatorHalls（エスカレーター）/ slopedHalls（坂）/ courtyard（中庭）
  - columnField（柱林）/ grandHall（大広間）/ verticalHall（縦長ホール）/ pitGallery（穴の回廊）
  - ceilingWells（天井井戸）/ splitHalls（分割ホール）/ loopMaze（ループ迷路）/ serviceMaze（狭い設備迷路）
- **施設の種類は 11 種**: 高級住宅 / 住宅 / 廃れた住宅 / 図書館 / ホテル / 美術館 / 屋内中庭 / 屋敷 / 屋内プール / バックルーム / 屋内遊び場。
- 種類ごとに「形の系統」（field = 区画が一面に広がる / atrium = 吹き抜け / suites = 部屋が連なる）が決まる。
- 空間の型 × 施設の種類の掛け算で、見た目のばらつきを出している。

**探索の目的**
- 「調査率」を 100% にして入口から戻る。フロアの一覧で、調査済み・調査の回数を記録している。

**特殊個室**
- フロアに 1〜2 室（50%）、普通の扉の向こうに別室がある。
- 異変は 15 種で、1〜3 個を重ねて出す。
  - 別の部屋の家具 / 大量の家具 / 単色 / 壁と床の欠け / 巨大 / 回転と大きさの異変 / 一か所に集まる家具 / 広がった部屋
  - RGB の照明 / 水中 / 炎と煙 / 果てしない通路 / 傾いた部屋 / 草原 / ひまわり畑

**部屋の課題（18 種）**
- 7 秒止まる / ゆっくり歩き続ける / 全力で走り続ける / 後ろ向きに歩く
- 時計を見続ける / 時計を見ないで進む
- 本をちょうど 8 組集める / 決まった通路を順に通る / 特定の区画を踏まない / 決まった順に区画を訪れる
- 遠くをズームで注視する / 椅子を押して戻す / その場で振り返る / 音量を 0 にする など。

**ミニゲーム（30 種）**
- ウォータースライダー / 傾いていく部屋 / 送風口の通路 / 落ちてくる天井 / ドミノの橋 / 天秤の床
- 振り子の通路 / 弾む床 / 崩れていく帰り道 / ボールプール / 赤い球 / 床を傾けて球を穴へ
- 迷路 / 黒い靄 / 視線のマネキン / 消える照明とマネキン / 動く照明の範囲 / 鏡で光をセンサーへ
- 非常電源 / サーチライト / 崩れる床 / 増水 / 逆走エスカレーター / 箱の橋
- 滑る床 / 回転する部屋 / 異変の廊下 / 変わる帰路 / だるまさんがころんだ / 霧の誘導灯

### 1.2 余白を歩く（仮説を 1 つずつ確かめる空間 + 組み合わせの別室）

**空間の並べ方**
- **空間 21 種を一本道につなぐ**。どの空間にも、確かめたい「仮説」が 1 つ付いている（H1〜H18）。例: 「足元が変わると、同じ道も変わる」。
- 21 種の内訳:
  - 基準の廊下 / 床素材の廊下 / 坂と階段と景色 / 幅の狭い道 / 踏む仕掛けの部屋（音を順につなぐ）
  - 人感センサー / 水を運ぶ / 低い天井と隙間 / 動く歩道 / 足跡とループ / 霧とランドマーク
  - 不安定な足場（崩れる・傾く）/ 重力の回廊（床 → 壁 → 天井）/ ガリバーの待合室（身体の大きさ）
  - 立ち止まると見える道 / 音の道しるべ / 弾む床 / 距離を飛び越える扉 / 玉乗りの通路 / バブルをまとう / 灯りを追って

**組み合わせの別室（6 種）**
- 基本の仕掛けを掛け合わせて作っている。
  - 低い天井 × 灯りについていく
  - 重力の変化 × 立体迷路 × 霧の目印
  - 細い道 × 玉乗り
  - 物を運ぶ × 止まると開く
  - 動く歩道 × 人感センサー
  - 足跡 × 拡大縮小 × 床素材
- **少ない基本の仕掛けを組み合わせるだけで、新しい部屋が作れる**ことを示している。

**作りの共通点**
- どの空間も同じ基底クラスから作る（buildZone / update / onEnter / onExit / reset / getSpawnPoint）。
- 失敗したら、その区間の最初か近くの足場から**すぐやり直せる**（閉じ込めない）。
- 照明は事前に焼き込んでいる（bake:lighting）。
- 調整パネル（歩行・カメラ・音の数値を JSON で書き出し・読み込み）と、空間ごとのアンケート（5 段階 + 自由記述）がある（v2 では採用しない）。

### 1.3 v1 にすでにあるもの
- **Modifier 42 種**: 照明の位相・重複番号・偽の出口・偽の空・霧・重力の向き・ループ・鏡のずれ・動く壁・観測で変わる接続・過去の窓・縮尺の異変・浅い水・滑る床・温度・乗り物・水の壁 など。
- **奇妙さ 25 種**: 柱の格子・間仕切り・一つだけの物・規則的な並び・照明のずれ・痕跡・転倒・散乱・積み重なり・部屋の中の部屋・内向きの窓・すぼまる廊下 など。
- **部屋の定義 112 種**。

### 1.4 3 つを比べて見えること
- **QR はフロア単位で作る**。区画の格子 + 廊下 + 高さのつなぎでフロアを丸ごと作り、そこに課題と別室を載せる。
  - v1 は「歩くたびに隣の部屋を 1 つずつ作る」ので、世界の形が歩いた順に左右される（継承計画 1 章の問題 1）。
  - QR の作り方なら、フロアは seed だけで決まる。**順番に依存しない世界**と、マルチプレイの両方に向いている。
- **WS は仕掛けを部品として組み合わせる**。仕掛けを「感じる部分（センサー）× 起きること（作用）× 空間」に分けておけば、組み合わせの数だけ部屋が増える。
- **v1 は見た目の異変が豊富**。ただ、遊びとして関わる仕掛けは少ない。v1 の Modifier・奇妙さは「部屋の状態」の層として残し、QR・WS 型の「関わる仕掛け」の層を新しく足すのが自然。

## 3. プロの作り方の調査

| 作り方 | 例 | 要点 | v2 への示唆 |
|---|---|---|---|
| **グラフを先に、空間を後に** | Unexplored（循環型ダンジョン生成）[1][2] | 位置を持たない「部屋と関係のグラフ」を先に作る。2 本の道でできる輪を単位に、鍵と錠などの型を当てはめ、輪の中に輪を入れ子にする | フロアの骨組みをグラフの型（F06・F07 など）として持つ。錠の代わりに「近道が開く」型にすれば閉じ込めない |
| **手作りの部屋 + 生成の配置** | Dead Cells [3]、Enter the Gungeon [4]、Edgar [5] | 部屋は人が作った型（外形 + 扉の候補位置）。グラフ（流れのファイル）が部屋の役割とつながりを決め、配置のプログラムが型を当てはめる。部屋の役割（宝・商人・戦闘・つなぎ）ごとに型を分ける | 「部屋の役割」（入口・つなぎ・仕掛け・目印・休憩・別室）を決め、役割ごとに部屋の型の候補を持つ |
| **必ず通れる道 + 型の部品** | Spelunky [6] | 入口から出口までの通れる道を先に決め、そこに型の部屋を当てる。部屋の中も小さな部品の型で埋める | 「本道は必ず通れる」を生成の最初に保証し、仕掛けは本道の脇か上に置く |
| **部品を並べて埋める** | WFC [7]、Bad North / Townscaper [8] | 隣り合ってよい部品の決まりから、矛盾のない並びを作る。Bad North は通れることを保ちながら並べる | 部屋の中の細部（棚の列・柱・天井の設備）を部品として並べる。全体の骨組みには使わない |
| **データで作る仕掛け** | Dungeon Siege の部品式オブジェクト（条件と動作の組の仕掛け）[9]、Unreal の Gameplay Tags / Effects / Cues [10][11] | 物を部品の組み合わせとして定義する。状態は「タグ」、変化は「効果」のデータ、見た目と音は「Cue」としてタグで呼ぶ（中身の処理と演出が分かれている） | 仕掛け = 感じる部品 × 判断 × 起きること の配線。演出は Cue としてクライアントだけに置く（サーバーと共有しやすい） |
| **異変の目録** | 8 番出口 [12][13] | 1 周に異変は最大 1 つ。異変の目録から出し、正しく見抜いた異変はそのプレイ中は二度と出ない | 認知の異変（2.13）は「目録 + 1 つまで + くり返さない」の決まりで出す |

## 4. 提案: v2 の実装方式

**一言で: 「フロアのグラフ → 空間の配置 → 部屋の中身」の 3 段で作り、その上に「部品を配線して作る仕掛け」と「部屋の状態を変える異変」の 2 つの仕組みを載せる。**

```
          worldSeed + フロアの座標
                   │
   ① フロアの骨組み（グラフの型）     役割つきの部屋とつながり。位置はまだ無い
                   │
   ② 空間の配置（区画の格子 + 外形の型） 部屋の位置・大きさ・高さ・廊下・階段
                   │
   ③ 部屋の中身（v1 の生成の段を整理）  形 → 仕掛け → 家具 → 奇妙さ → 汚れ
                   │                     各段で 到達確認 → だめなら取り消し
                   ▼
              FloorLayout（純データ）
              │                  │
     core/sim（サーバーと共有）   client（描画・音）
     仕掛けの部品の状態と tick     Cue（演出）を受けて見せる
```

### 4.1 生成の単位をフロアにする（いちばん大事な変更）

- フロアは `(worldSeed, フロアの座標)` だけから**丸ごと一度に作る**。歩いた順番に左右されない。
  - これで継承計画 1 章の問題 1（世界が歩いた順で変わる）が根本から消える。2 人が別の方向へ歩いても同じフロアになる。
- フロアどうしは、決まった数の「階の出入口」（階段・エレベーター・穴・乗り物）でつなぐ。フロアをどこまでもつなげれば、v1 と同じく果てしない探索になる。
- 1 フロアの大きさは、QR と同じ 70 m 四方程度から始める。大部屋（Legendary）は 1 フロア = 1 部屋として扱う。

### 4.2 ① フロアの骨組み = グラフの型

```ts
// v2/core/gen/floor/graph.ts（型の案）
type SlotRole = 'entry' | 'exit' | 'hub' | 'connector' | 'gimmick' | 'landmark' | 'rest' | 'side' | 'secret';
type EdgeKind = 'door' | 'opening' | 'stairs' | 'ramp' | 'crawl' | 'hole' | 'slide' | 'portal' | 'oneWay' | 'shortcut';
interface Slot { id: string; role: SlotRole; size: 'S' | 'M' | 'L' | 'XL'; tags: string[]; intensity: 0 | 1 | 2 | 3 }
interface SlotEdge { a: string; b: string; kind: EdgeKind; opensFrom?: string /* 近道: こちら側からだけ開く */ }
interface FloorGraph { slots: Slot[]; edges: SlotEdge[]; mainPath: string[] /* 必ず通れる道 */ }
```

- **型（パターン）を組み合わせて作る**。F06 二重ループ・F07 入れ子のループ・F08 ハブ・F09 櫛形・F10 環状・F25 緊張と解放 などを、グラフの書き換え規則として持つ。
- **錠と鍵の代わりに「近道」**を使う。奥の仕掛けを解くと、入口近くへの近道（`oneWay` / `shortcut`）が開く。解かなくても本道で戻れる。
- **緩急（intensity）**: 仕掛けの強さ 0〜3 を、本道に沿って「上げて → 休憩 → 上げる」の波になるように並べる（Gungeon の流れと WS の仮説の並べ方）。

### 4.3 ② 空間の配置 = 区画の格子から始める

- まず QR と同じく、**区画の格子 + 廊下 + 高さのつなぎ**で作る。区画を 1 つ以上まとめて大きな部屋にし、L 字・コの字は区画を組み合わせて作る。
  - v1 の `footprint.ts`（矩形の集合・壁区間・ソケット）を移して使う。
- グラフの各部屋を区画に割り当て、隣り合う区画どうしを廊下か直結でつなぐ。床の高さの差は、edge の種類（stairs / ramp / slide）で埋める。
- 格子に収まらない型（螺旋 F12・同心円 F11 など）は、あとから**外形の型**（Edgar と同じ「外形 + 扉の候補」）を足して配置する。最初から自由配置の計算に頼らない。

### 4.4 ③ 部屋の中身 = v1 の段の並びを整理して使う

```
部屋の型（S01〜S30） → 仕掛け（4.5） → 家具・装飾（施設の種類ごと） → 奇妙さ・異変（4.6） → 汚れ・デカール
```
- 各段は別々の乱数列を使い（v1 の `fork(tag)`）、段ごとに**到達確認 → だめなら取り消し**（v1 `oddity/index.ts` の方式。QR も到達判定で置き場所を決めている）。
- 部屋 ID の直書きは禁止。違いは「施設の種類 × 部屋の型 × 仕掛け × 異変」のデータの組み合わせで出す（QR の空間の型 × 施設の種類の考え方）。

### 4.5 仕掛け = 部品を配線して作る

WS の組み合わせの別室・Dungeon Siege の「条件と動作」・Unreal の Tags / Effects / Cues を合わせた形にする。

**部品は 3 種類**

| 種類 | 例 |
|---|---|
| 感じる部品（Sensor） | 区画に入る / 止まっている時間 / 速さ / 後ろ向き / 見ている・見ていない / ズームしている / 音量 / 持っている物 / 踏んだ順番 / 人数（将来） |
| 判断の部品（Logic） | かつ・または / 順番 / 時間 / 回数 / 一度きり（ラッチ）/ 乱数（seed 由来） |
| 起きること（Actuator） | 扉を開ける / 床を動かす（経路・回転・傾き）/ 崩す / 照明 / 重力の向き / 身体の大きさ / 押す力 / 移動させる / 道を見せる / 足跡を残す / 記録を埋める / 体力を変える（v2） |

**仕掛けの定義（案）**

```ts
// v2/core/gen/gimmicks/movingWalkwayWithSensorLights.ts（WS の「運ばれる光の道」を例に）
export default defineGimmick({
  id: 'walkway.sensorLights',
  axes: ['move.carry', 'light.reactive'],    // 何に作用するか（組み合わせの判定に使う）
  role: 'gimmick', intensity: 1,
  needs: { length: [24, 60], width: [2.5, 4], sockets: 2 },  // 置ける部屋の条件
  params: { speed: [0.8, 1.6], lampSpacing: [3, 5] },         // seed から選ぶ範囲
  build(ctx) {                                 // 純データ: 箱・ゾーン・部品を足す
    const belt = ctx.addMover({ path: ctx.mainLine(), speed: ctx.p.speed });
    const lamps = ctx.addLamps({ spacing: ctx.p.lampSpacing, initial: 'off' });
    ctx.wire(ctx.sensor.near({ target: 'player', radius: 4 }), lamps.each.turnOn, { holdSec: 2 });
  },
  validate: { reach: ['in→out', 'out→in'] },   // 逆向きでも通れること（閉じ込めない）
  failure: 'none',                              // 失敗が無い仕掛け。崩れる床などは { respawn: 'segmentStart' }
  multiplayer: 'shared',                        // 共有か、人ごとか（将来）
  cues: ['sfx.walkway.hum', 'light.sensorClick'],
});
```

- **組み合わせの自動生成**: 仕掛けごとに作用の軸（move / light / sound / sight / time / gravity / body / carry）を持たせる。
  - 軸がぶつからない 2〜3 個を組み合わせて、組み合わせの別室を作る（例: 低い天井 × 灯りを追う）。
  - 同じ軸を 2 つ重ねる組み合わせ（動く歩道 × 回転する床）は、表で許可したものだけにする。
- **状態と演出を分ける**: 部品の状態（開いた・崩れた・灯りの番号）は小さな純データで `core/sim` が固定 tick で進める。音・光り方・揺れは Cue としてクライアントが演出する。
  - こうしておけば、マルチプレイのときに同期するのは部品の状態だけで済む。
- **閉じ込めないことを機械的に保証する**: `validate.reach` で、仕掛けが「最悪の状態」（扉が閉じたまま・床が崩れた後）でも入口へ戻れるかを生成時に確かめる。だめならその仕掛けは置かない。

### 4.6 異変 = 部屋の状態を変える層

- QR の特殊個室の異変 15 種・v1 の Modifier・奇妙さを、**layout を書き換える純関数**（共有）と**見せ方**（クライアント）に分けて移す。
- 認知の異変（2.13）は 8 番出口の決まりで出す: 目録から 1 つまで、見抜いた異変はくり返さない。

### 4.7 作るための道具

- **仕掛けの実験場**: `?lab=<仕掛け ID>&seed=` で、仕掛け 1 つだけの部屋を開く。WS の調整パネルと同じく、params を画面で動かして JSON に書き出せるようにする。
- **ヘッドレスの検査**（v1 の seam-stats の後継）: 次の 4 つを数値で出す。
  - N 個の seed でフロアを作って、本道を必ず通れるか
  - どの仕掛けからも戻れるか
  - 描画の予算（描画呼び出しの回数・照明の数）を守れているか
  - 決定論: 2 つの順番で作っても同じになるか

### 4.8 なぜこの方式か

- **案を増やすほど速くなる**: 仕掛けが部品の配線なので、部品が 30 個あれば組み合わせで数百の部屋ができる。新しい案の多く（2 章）は、既にある部品の新しい配線で作れる。
- **閉じ込めないことと決定論を、生成時に機械的に確かめられる**: どちらも人の注意に頼らない。
- **v2 の他の計画とつながる**: フロア単位の生成は継承計画の P3（順番に依存しない世界）そのもの。状態と演出を分けることは P4（マルチプレイ）の前提。体力も、起きることの部品を 1 つ足すだけで済む。
- **v1 とプロトタイプの資産が活きる**: v1 の footprint・到達判定・段の並び・異変と、QR の区画の格子、WS の仕掛けの作り方を、どれも捨てずに使える。

## 6. 決まったこと（2026-10-02）

1. **生成の単位はフロア**（4.1 のとおり）。
2. **仕掛けはバリエーションの要素**。報酬は置かず、仕掛けを普通とは違うやり方で使うと隠し通路・隠し部屋が見つかる形にする（v2-plan.md 4 章。2.15 のミニゲームも、成功の報酬ではなく隠しの仕掛け元として扱う）。
3. **QR・WS は自由に流用してよい**（コードも含む）。
4. **最初の 10 種の並びはこのままでよい**。ただし実装は、考えた仕掛けをまとめて導入する（v2-plan.md 7 章）。
