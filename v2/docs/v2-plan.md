- **v1 の部屋 1 つずつの生成 → フロア単位**（V2-1）。

## 3. ゲームの芯

1. **探索して地図を埋める**（v1 のまま）。フロアごとに調査率 [QR] が上がり、フロア図鑑に記録される。
2. **フロアはどれも違う**。フロアの形の型 × 空間の型 × 施設のテーマ × 仕掛け × 異変の組み合わせで作る。
3. **表の道と裏の道**。
   - 普通に進めば、本道で次のフロアへ行ける。
   - 仕掛けを「普通とは違うやり方」で使うと、隠し通路・隠し部屋・裏のフロアが見つかる。
   - 見つけたものは地図と図鑑に残る。
4. **閉じ込めない**。どの仕掛けも、どの隠し先も、来た道か先の道へ必ず出られる。

## 4. 隠し発見の仕組み（裏の道）

### 4.1 考え方
- どの仕掛けにも、**多くの人がする振る舞い（表）**と、**あえてする振る舞い（裏）**がある。
  - 例: 床が傾くと少し物が転がる → 普通の人は行き止まりと思うか、見えている扉へ行く（表）。わざと傾け続けて物を大量に動かす（裏）。
- 裏の振る舞いを「感じる部品」（Sensor）で捉え、隠し場所を明かす。仕掛けの部品の配線（gimmicks-and-structures.md 4.5）にそのまま載る。
- **隠し方は 2 つの型がある**（2026-10-02 ユーザー確認）。どちらもバリエーションとして使い、割合は調整表で変えられる。
  - **存在型**: 扉や穴は**最初から存在し、描画もされる**。物の陰・落ちた先・暗がり・視線の外など、位置的に見えにくいだけ。裏の振る舞いは「そこへ行き着く・見えるようにする」手段で、条件の判定は要らない（例: 床を傾けて物をどかす・細い道から落ちる・光を無視して暗がりへ行く）。
  - **出現型**: 条件を満たして**初めて道や扉が現れる**。それまでは描画も当たり判定も無い（例: パズルを解くと扉が現れる・立ち止まると道が見える）。現れる瞬間を演出として見せる。
- **公平さの決まり**: 隠し場所には、共通の「目印の言葉」を使う。プレイヤーが学べるようにするため。
  - 例: すきま風で埃が揺れる / 壁の継ぎ目から光が漏れる（v1 の DoorLeak）/ 足音のこもり / 壁紙の継ぎ目のずれ / 床の目地の違い。
  - Zelda のひび割れた壁や Inside の黄色い配線のように、目印は弱く、でも一貫させる [S1][S2]。
- **置き場所の決まり**: Binding of Isaac は、隠し部屋を「複数の部屋に隣接する場所」に置きやすくし、入口の前は必ず歩ける状態に保つ [S3]。v2 も、隠し場所の前は歩ける・明かす操作ができる場所にだけ置く。

### 4.2 データの形

```ts
// v2/core/gen/secrets/types.ts（案）
interface SecretHook {                 // 仕掛けの定義が持つ「裏の振る舞い」の候補
  id: string;                          // 'tilt.clearProps' など
  weight: number;                      // この仕掛けに付く確率の重み
  reveal: SensorSpec;                  // 裏の振る舞いを捉える部品（例: 区画の物の数が 30% 以下）
  modes: ('present' | 'appear')[];     // 使える型: 存在型 / 出現型（両方なら調整表の重みで引く）
  conceal: ConcealKind;                // 存在型の隠し方: 'underProps' | 'belowFall' | 'inDark' | 'behindWall' | 'outOfSight' | …
  appearCue?: string;                  // 出現型の現れ方の演出（'slideOpen' | 'fadeIn' | 'tilesRise' …）
  placement: PlacementRule;            // 隠し場所をどこに置けるか（床・壁・下の階・天井）
  tell: TellKind[];                    // 目印（すきま風・光漏れ・音のこもり …）
  intensity: 0 | 1 | 2 | 3;            // 見つけにくさ
}
interface SecretSlot {                 // フロアのグラフに足される隠し先
  id: string; host: string /* 仕掛けのある部屋 */; hook: string;
  kind: 'passage' | 'room' | 'privateRoom' | 'shortcut' | 'bFloor' | 'cache';
  exits: string[];                     // 隠し先から出られる先（閉じ込めない）
}
```

### 4.3 生成の手順（確率で仕込む）
1. **本道を作る**: フロアの骨組みと空間の配置を作り、本道（入口 → 出口）が裏の振る舞い無しで通れることを確かめる。
2. **隠しの数を決める**: フロアごとに「隠しの予算」を引く。`予算 = 基本 + 深さ × 係数 + フロアの希少度の加算`（例: 平均 1.2 個、Legendary 以上は 2〜3 個）。0 個のフロアもある。
3. **仕掛け元を選ぶ**: フロアの中の仕掛けのうち、SecretHook を持つものを候補にする。`hook.weight × 部屋の希少度 × 空き空間の大きさ` の重みで引く。
4. **場所を取っておく**: 隠し場所に必要な空間（隠し部屋の外形・隠し通路の経路・下の階の受け止め）を予約する。
   - フロアを丸ごと作るので、隣の空き区画・下の階・壁の厚みを先に押さえられる。v1 の部屋 1 つずつの生成ではこれができなかった。
5. **隠し先の中身を引く**（4.6 の表から）。
6. **入れ子**: 低い確率で、隠し先の中にさらに隠しを仕込む（2 段まで）。
7. **検証**（4.4）。だめなら、その隠しだけ取り消して次の候補へ。

### 4.4 検証（生成時にプログラムで確かめる）
| 検証 | 内容 |
|---|---|
| 本道 | 裏の振る舞いを一切しなくても、入口から出口へ通れる |
| 隠れている（存在型） | 本道の上の点から隠し場所が直接見えない（視線の抽出検査。時間の上限を超えたら省く・切ってもよい。V2-10）。到達できるかどうかは問わない（最初から存在するので） |
| 隠れている（出現型） | 条件を満たす前は、隠し先へ到達できない（現れていないので）。視線の検査は要らない |
| 明かせる・行き着ける | 裏の振る舞いが物理的に可能（存在型は「行き着ける」、出現型は「条件を満たせる」）。例: 傾ける仕掛けでは、決まった入力で物理を数秒ヘッドレスに回し、本当に物がどいて穴が見えることを確かめる（6.1 の決定論の物理で再現できる） |
| 閉じ込めない | 明かした後、隠し先へ行けて、隠し先から本道か先へ戻れる。落ちる型（細い道から落ちる）は、落ちた先から上がる道があること |
| 決定論 | 同じ seed なら同じ隠しが同じ場所にできる |

### 4.5 ご提示の 4 つを形にすると

| 仕掛け | 表の振る舞い | 裏の振る舞い（明かす条件） | 隠し方（主な型） | 目印 |
|---|---|---|---|---|
| 床を傾ける部屋（物が転がる） | 少し転がして、行き止まりと思うか見えている扉へ | 傾け続けて物を大量に動かす（区画の物が一定割合を下回る） | 物の山の下の床の穴・物に隠れた壁の扉（存在型） | 物の隙間から漏れる光・すきま風で揺れる紙 |
| 細い道 | 渡り切って普通の部屋へ | 落ちる（落下の区画に入る） | 下の階の受け止めの床に扉（存在型） | 下から聞こえる環境音・下の階の灯り |
| 導く光 | ついていって通常の扉へ | 光を無視して離れる（光から一定距離以上・一定時間）/ 光が避けた場所へ行く | 光が当たらない暗がりの扉（存在型。蓄光でぼんやり見える）/ 光から離れると現れる扉（出現型） | 光が一瞬そちらを避ける |
| 謎のパズルと行き止まり | 行き止まりなので引き返す | パズルを解く | 行き止まりの壁が開く / 隠し扉が現れる（出現型） | パズルの近くの、壁の継ぎ目のずれ |

**床の傾け方**: ボタンを使わず、**プレイヤーの立ち位置の方へ床が傾く**（天秤 [QR] と同じ）。スマホでもそのまま遊べ、「わざと傾け続ける」という裏の振る舞いも自然に生まれる。

### 4.6 隠し先の中身（引く表）

2026-10-02 のご確認を受けて決め直した（隠し扉の先はレアな部屋か、そこへつながる通路。行き止まりのレア部屋はあってよいが、全部が行き止まりにはしない）。
重みは調整表の `secrets.dest.*`・`secrets.rare.*`、行き止まりでない隠しの最低数は `secrets.throughMin`。実装は `core/gen/secrets/index.ts`。

| 行き先 | 内容 | 既定の重み |
|---|---|---|
| 行き止まりのレア部屋 | 入口の扉のすぐ先のレア部屋 | 25 |
| 隠し通路 → レア部屋 | 細い設備通路（まっすぐ / 1 回曲がる）の先に、扉の付いたレア部屋 | 25 |
| 隠し通路 → 別の部屋（通り抜け） | 通路（まっすぐ / L 字 / 外を回る U 字）がフロアの別の部屋・廊下へ抜ける。出口は壁と同じ色の扉。出現型の出口は通路の側からしか開かない（先に出口側から入れないように） | 30 |
| 下のフロアへの穴 | 穴のある部屋。落ちると 2 つ先のフロア | 12 |
| 裏のフロアへの穴 | 穴のある部屋。落ちると裏のフロア（同じ配置で、照明・材質が違う） | 8 |

- 入口はすべて扉（開けるまで先は見えない）。存在型は壁と同じ色の扉、出現型は壁が消えると扉が現れる
- 隠しが 2 つ以上のフロアでは、行き止まりでない隠し（通り抜け・穴）を 1 つ以上にする
- レア部屋の種類: 白い私室（大きすぎる椅子）・小さな劇場・水の部屋・展示室・書庫・機械の部屋・遊戯室・温室・長椅子の部屋・灯りの小部屋。
  選んだ種類が収まらなければ小さい種類にする。中身は区画の中身の作り方（テーマ）で置き、白い私室・長椅子・灯りの小部屋・穴の部屋はここで決める
- 隠し場所の区画は入るまで暗く、入ると灯る
- 次の段階で足すもの: 特殊個室 [QR] の異変の重ね掛け・v1 の Legendary / Mythic の大部屋・モニュメント・図鑑の記録・入れ子（次の隠しの手がかり）

### 4.7 裏の振る舞いの案（ご提示の 4 つ以外）

**移動と身体**
- 動く歩道を逆走し切る → 始点の裏の点検口
- 逆走エスカレーターを上り切らず、途中の踊り場で止まる → 横の扉
- 弾む床で何度も跳び、天井の点検口に届く
- 低い天井の通路で、しゃがんだまま脇の隙間へ入る
- 重力の回廊で、天井を歩いている途中で横道へ → 天井側の扉
- 身体が小さいまま家具の下へ → 壁の小さな穴
- 玉乗りの通路で、球に乗ったまま脇の坂を下る
- バブルをまとったまま壁に何度もぶつかる → 薄い壁が割れる
- 回る床の中心ではなく縁に乗り続ける → 遠心力で外周の扉へ
- 送風の通路で、わざと強風に飛ばされる → 上の通気口
- 増水を待ち、水位が上がりきってから泳ぐ → 天井近くの開口
- ウォータースライダーの途中で、流れに逆らって脇の溝へ
- 振り子に飛び乗る → 振り子の届く高い棚
- ボールプールの深い所に潜る → 底の扉
- 縮むトンネルを、しゃがまずに後ろ向きで戻る → 来た時と違う出口

**光と闇**
- 人感センサーの灯りをつけないよう、ゆっくり暗闇を進む → 蓄光の扉
- 消える照明で、真っ暗な間に進む → 暗い時にだけある扉
- 鏡の光をセンサーではなく、何もない壁に当てる → 壁が開く
- 懐中電灯を消す → 暗闇でだけ光る目印
- サーチライトにわざと見つかる → 戻される先が、隠し通路の前
- 霧の誘導灯の、偽の灯りの方をたどる → 霧の奥の小屋

**音**
- 音の道しるべと逆の、無音の方へ行く → 無音の部屋
- 足音を立てない（しゃがみ歩き）で通ると、別の扉の気配がする
- 音をつなぐ扉で、決まった順と逆に鳴らす → 別の扉
- 壁の向こうの生活音がする壁に、長くもたれる（止まる）→ 壁が扉になる

**視線と観測**
- 視線のマネキンが見ている方向をたどる → マネキンの視線の先の扉
- だるまさんがころんだで、わざと動いて捕まる → 連れて行かれる先が隠し部屋（体力は減らさない）
- 時計を見ないまま長くいる → 時計が消え、時計の跡が扉になる
- 遠くの看板をズームする → 小さな文字が隠し部屋の番号（エレベーターで押す）
- 出口の前で振り返る [QR] → 来た道の壁に扉
- 記念撮影する → 写真にだけ写る扉（写った場所へ行くと開く）
- 監視カメラのモニターで、自分のいない部屋の扉が開いているのを見る

**物を運ぶ・置く**
- 水を一滴もこぼさず満杯で運ぶ → 台が沈んで扉
- 待つ扉で、違う荷物を持って待つ → 別の扉
- 本を 1 冊も集めない / 全部集める → それぞれ別の扉
- 椅子を全部どかす → 床下収納
- 物を全部同じ向きにそろえる → 壁の一部がずれる
- 拾った物を、元の部屋に戻す → 戻した部屋に新しい扉

**床と足場**
- 崩れる床を、わざと崩して落ちる → 下の階の隠し通路
- 崩れていく帰り道で、帰らずに奥へ進む → 崩れた先の下の階
- ドミノの橋で、決まった順と違う順に倒す → 別の溝に橋
- 立ち止まると見える道で、さらに長く止まる → 2 本目の道
- 足跡のループを逆回りする → 自分の足跡が無い場所に扉
- 天秤の床に物を載せて釣り合わせる → 真ん中の床が下がる

**空間と認知**
- 異変の廊下で、異変を見つけてもそのまま進む → 異変の部屋に入れる
- 閉じた輪の廊下を逆向きに何周もする → 輪がほどける
- 距離を飛び越える扉の、枠の裏側から入る → 別の部屋へ
- 地図の空白の場所の壁に行く → 壁が扉になる
- 同じ部屋が並ぶ所で、1 つだけ違う部屋の違う家具に触れる
- エレベーターで、存在しない階のボタンの順に押す（v1 U18 の発展）
- 自販機の同じボタンを何度も押す → 出てくる物が鍵になる（v1 U04 の発展）
- 窓の前で長く立ち止まる → 窓の外の部屋に入れる

**パズル（行き止まりの部屋に置く型）**
- 手がかりが別の部屋にある数字錠（案内板の数字・時計の時刻・部屋番号）
- 色の照明を混ぜて、決まった色にする
- 部屋中の時計の針を、同じ時刻に合わせる
- 床のタイルを入れ替えて絵を完成させる（v1 M07 の発展）
- 影絵: 照明と物の位置を合わせ、壁に扉の形の影を作る
- 鏡を並べて、光を部屋の奥へ通す
- 音の高さの順に、ベルを鳴らす
- 家具の配置を、壁の写真と同じにする
- 重さの違う箱を、天秤の両側で釣り合わせる
- 迷路の模型で球を転がし、本物の迷路の隠し出口を知る
- 消えた照明を、電球を運んで元の順に戻す
- 足跡の模様どおりに床を踏む

**なぜフロア単位だとパズルが作りやすいか**: 手がかりの部屋と答えの部屋を、同じフロアの中で同時に決められる。v1 のように隣の部屋がまだ無い状態では、手がかりを置けなかった。

## 5. 生成の全体像（フロア単位）

```
① フロアの希少度とテーマを引く（深さ・v1 のレア度の重み）
② フロアの骨組み（グラフの型: ループ・ハブ・櫛形 …）→ 本道を決める
③ 空間の配置（区画の格子 [QR] + 外形の型 + 高さのつなぎ）
④ 仕掛けを割り当てる（緩急の波・作用の軸の組み合わせ）
⑤ 隠しを仕込む（4.3。場所の予約 → 中身 → 入れ子）
⑥ 部屋の中身（部屋の型 → 家具 → 奇妙さ・異変 → 汚れ）。各段で到達確認 → だめなら取り消し
⑦ 検証（本道・隠し・閉じ込めない・決定論・描画の予算）
          ▼
    FloorLayout（純データ。サーバーとクライアントで共有）
```

- 部屋の定義の扱い: v1 の 112 定義を「施設のテーマ」（オフィス・ホテル・学校 …）・「部屋の型」・「異変」に分けて表にする。例: C02 オフィス廊下 = オフィス × 長い通路 × 異変なし、U14 = オフィス × 部屋 × 受話器の異変。
- 特別な定義（E03 横向きホテル・M14 照明一本の虚空 など）は、「特別なフロア」として 1 フロアを丸ごと使う。

## 6. 技術の選び方（調べた結果）

### 6.1 物理: 転がる物には Rapier の決定論版を使う
- 床を傾けて物が大量に転がる・ドミノ・球・振り子・崩れる床には、剛体の物理が要る。v1 の当たり判定（箱の押し出し）では足りない。
- **Rapier**（Rust 製、WASM で JavaScript から使える）を使う。
  - JS / WASM 版は、同じ版・同じ初期条件なら、ブラウザ・OS・CPU が違っても同じ結果になる。
  - 状態のスナップショットのハッシュも一致する [S4]。
- 使い方:
  - 生成時の検証（4.4「明かせる」をヘッドレスで回す）
  - 将来のマルチプレイでの同期
- プレイヤー本体の移動は、v1 で調整済みの自前の処理（固定 tick の AABB）を使う。Rapier にはキネマティックな体として渡し、物を押せるようにする。
- 2026-10-02 の確認: `@dimforge/rapier3d-deterministic-compat` 0.21.0 を採用。Node で同じ条件を 2 回回してスナップショットのハッシュが一致（`v2/tests/rapier-determinism.test.ts`）。120 体 × 300 step が約 125 ms（1 step 0.4 ms、PC）。読み込みは約 4.4 MB（gzip 1.7 MB）なので、物理を使うフロアに入る前に動的に読み込む。
- 剛体はフロアの中の「動く部屋」だけで動かす。見えていない部屋の物は眠らせる。

### 6.2 描画: フロア全体を持ち、見える部屋だけ描く
- **cell and portal**: 部屋をセル、扉と窓をポータルとし、カメラのいる部屋から、見えるポータルの先だけをたどって描く。屋内の建物には古くから使われている方法 [S5]。
- 扉を閉めれば、その先は描かない（v1 の「閉じた扉の向こうを描かない」の一般化）。
- 部屋の構築は v1 の分割構築（RoomBuildJob）を使う。照明はフロア単位で Web Worker で焼き込む（v1 の Lightmap + WS の焼き込み）。
- 継ぎ目の無い空間の移動（W03 距離を飛び越える扉 など）は、ステンシルのポータル描画にする（gimmicks-and-structures.md 3 章）。

### 6.3 仕掛け: 部品の配線 + Cue
- gimmicks-and-structures.md 4.5 のとおり。感じる部品 × 判断 × 起きること の配線。状態は `core/sim`、演出は Cue としてクライアント。
- 隠し発見（4 章）は、この配線に SecretHook を足すだけで作れる。

### 6.4 プロトタイプのコードの流用（V2-4・V2-8）
- 公開されているのは、ひとまとめに圧縮されたビルド後のファイルだけ。元のソースは求めない（V2-8）。
- 圧縮されても、仕組み（処理の流れ）・数値（寸法・速さ・確率）・文字列は残る。必要になった仕掛けごとに、ブラウザペインで該当部分を読み、v2 の仕掛けの定義として作り直す。
  - 例: QR のフロア生成（区画 5×5・間隔 8 m・深さ優先 + ループ）、WS の空間の基底クラス（buildZone / update / reset / getSpawnPoint）は、今回の調査で読み取り済み。
- 失うのは、元の変数名・コメント・ビルド前の構成だけ。v2 は仕掛けを部品の配線で作り直すので、元のコードをそのまま移す場面はもともと少ない。

### 6.5 調整値は 1 か所にまとめる（V2-9）
- 生成と仕掛けの数値（隠しの予算・確率の重み・見つけにくさ・目印の強さ・仕掛けの出方・緩急・フロアの大きさ など）は、すべて `v2/core/config/tuning.ts` の 1 つの表に、型と既定値と範囲つきで置く。コードの中に数値を直書きしない。
- 変え方:
  - 表の値を書き換える（恒久的な変更）
  - URL の `?tune=secrets.perFloor=2.0` で一時的に上書きする
  - 開発用の調整パネルで動かし、JSON で書き出す
- ヘッドレスの検査が、変えた値で多数の seed を回し、隠しの数の分布・仕掛けの出方を数値で返す。値を変えた結果をすぐ確かめられる。
- 調整表の版を、フロアの生成結果の保存に含める。値を変えても、遊んでいる世界が勝手に作り変わらないようにするため。

## 7. 「まとめて導入」の進め方（V2-5）

**基盤だけは順に作り、仕掛けの中身は一斉に作る。main へは 1 回でまとめて入れる。**

### 7.1 基盤（順番に作る。並行できない）
1. `core/sim`: 固定 tick・部品（Sensor / Logic / Actuator）・状態の保存・Rapier の組み込み
2. `core/gen`: フロアの骨組み・区画の配置・部屋の中身の段・仕掛けの割り当て・隠しの仕込み・検証
3. `client`: v1 の描画・音の移植（継承計画の A・B 区分）・cell and portal・仕掛けの実験場（`?lab=<ID>&seed=`）・調整パネル
4. **部品の網羅**: 案の一覧（約 280 + 裏の振る舞い約 60 + パズル 12）を全部読み、必要な部品を洗い出して先に作る。目安は感じる部品 25・起きること 30 程度。

### 7.2 仕掛けの中身（一斉に作る）
- 案の一覧を、台帳 `v2/core/gen/catalog.ts`（ID・分類・作用の軸・裏の振る舞い・状態）にする。
- 仕掛け 1 つ = ファイル 1 つ（`gimmicks/<分類>/<ID>.ts`）。v1 の Modifier と同じく、置けば自動で登録される。
- 分類ごとに担当を分け、並行して作る。担当ごとに持つファイルを固定し、共有ファイルの変更は依頼ファイルで統合担当へ回す（v1 の requests.md 方式）。
- **合格の条件**（全部の仕掛けで同じ。プログラムで確かめる）:
  - 実験場で開ける
  - 検証（本道・閉じ込めない・決定論・描画の予算）を通る
  - 裏の振る舞いがあれば、隠しの検証（4.4）も通る

### 7.3 統合
- 全部の仕掛けを入れた状態で、seed を多数回してフロアを作り、次の 3 つを数値で確かめる。
  - 仕掛けの出方の偏り
  - 隠しの数の分布
  - 描画の予算
- 確かめ終えたら、1 回のマージで main に入れる。

### 7.4 危うい点と対策
| 危うい点 | 対策 |
|---|---|
| 量が多く、出来にむらが出る | 合格の条件をプログラムで確かめる。部品を先に揃え、仕掛けは配線を主にする |
| 物理と大量の物で重くなる | 動く物は「見えている動く部屋」だけ。スマホは物の数の上限を下げる |
| 隠しが見つからなさすぎる・見つかりすぎる | 隠しの予算・見つけにくさ・目印の強さを数値の設定にし、実際に遊んで調整する |
| 基盤の設計の誤りが、後で全部の仕掛けに響く | 基盤の段階で、性質の違う仕掛け 10 種（gimmicks-and-structures.md 5 章 G1）を先に作り、部品の設計を確かめてから一斉に作る |

## 8. 段階（継承計画の P と、仕掛けの G をまとめたもの）

| 段階 | 内容 | 終わりの目安 |
|---|---|---|
| 1 基盤 | core/sim（部品・固定 tick・Rapier）・v1 の描画と音の移植・実験場 | 試験の部屋 1 つで、v1 と同じ質感のまま、配線した扉と転がる物が動く |
| 2 生成 | フロア単位の生成（骨組み・区画・中身・検証）・cell and portal | seed だけで 1 フロアを作って歩ける。順番を変えても同じ |
| 3 部品の確認 | 性質の違う仕掛け 10 種 + 隠し 4 種（4.5）を作り、部品の設計を確かめる | 10 種と 4 種がどれも合格の条件を通る |
| 4 一斉に作る | 案の一覧の全部の仕掛け・裏の振る舞い・パズル・異変 | 全部が合格の条件を通る |
| 5 統合 | 出方の調整・地図と図鑑・調査率・スマホ・性能 | 多数の seed で偏りと予算が基準内。main へ 1 回でマージ |
| 6 以降 | 体力（規則が決まってから）・マルチプレイ（後回し） | |

段階 3 までは、仕掛けの数より「部品の設計が正しいか」を優先する。段階 4 で一斉に増やす。
