# Seam 削減の計測結果（tools/seam-stats.mjs）

計測日: 2026-09-16。担当 F3（WorldManager: Seam 削減・施錠行き止まり・crawl Adapter・接続フック）。

## 方法

```bash
node tools/seam-stats.mjs                      # 10 seed × 100 部屋踏破（既定）。console.table + 合計行
node tools/seam-stats.mjs --md                 # この文書と同じ Markdown 表
node tools/seam-stats.mjs --json               # 機械可読
node tools/seam-stats.mjs --seeds 42,1 --rooms 60
node tools/seam-stats.mjs --root <別のプロジェクトルート>   # 変更前のバックアップなどと同条件で比較
```

- vite 8 同梱の rolldown で `src/world/WorldManager.ts` + RoomGraph + data を Node 用 ESM に束ねて実行する（npm install 不要、DOM シム不要。WorldManager 系は DOM 非依存）。
- 踏破は Game.enterRoom と同じ順序（markVisited → `frozen` = 現在 + 直前の構築集合（現在 + placedNeighbors）+ 訪問済み → prepareRoom）で、未訪問の配置済み隣室を優先する DFS 徒歩。行き止まりで戻る先も無いときだけ意図的 Seam 扉を通る。
- 指標: `WARN seam fallback`（緊急 Seam）と `WARN dead-end lock`（施錠行き止まり。部屋ごとに 1 回）の件数、前室ノード数、施錠扉率、部屋の重なり（配置済み AABB の重なり組数）、決定論（同 seed 2 回で `graph.toJSON()` 一致）、`toJSON → fromJSON` 後の全ノード `layoutFor` のソケット一致。
- 「変更前」は scratchpad の `backup_src_v2`（v1.2 実装、Seam フォールバックあり）を `--root` で束ねたもの。同じ 10 seed × 100 部屋。

## 入れた変更と効果の内訳

| 施策 | 内容 | 備考 |
|---|---|---|
| Q3 = B | 最終手段の Seam 化を施錠に変更（`WARN dead-end lock at <room>/<portals>`。部屋ごとに 1 回） | 緊急 Seam 0 件 |
| SEAM-1 | 側道扉（mustSucceed=false）は前室を挿入せず即施錠 | 前室 1024 → 95 |
| SEAM-2 | 進行保証は候補扉全てを段階ごとに試す（通常抽選 → 新設 → 小部屋 → 前室） | 1 本目で打ち切らない |
| SEAM-3 | 未構築・未凍結（`canRelayout`）の部屋にだけ新設ソケット（最大 1 本、外側の枡 3×7.5 → 2.2×5 → 1.3×3.6） | 新設 120 件 / 1000 踏破 |
| SEAM-4 | SmallRoom / Restroom 系（Common/Uncommon・実装済み）から一様再抽選（`smallOnly`） | 56 件 |
| SEAM-5 | 前室の下限 2.0 m（転回時は側面扉を中央に置く戸袋型）、長さ [4,6,8,3,2]、連鎖は 2 つまで | Adapter 出口の枡は部屋と同じ 2.6×3.2（3.6×3.6 は 41 → 52 と悪化） |
| SEAM-7 | 直線廊下（footprint 1 矩形）も growToFill 対象（長手 z1、幅は 5.0 m 上限） | CorridorGenerator が `mainRect` を読むまで効果なし（phase1-requests 参照） |
| 近接判定 | findWallBehind / 新設ソケット / 直結の既存ソケット近接判定を 1.6 → 3.6 m | 再生成で既存の出口が動くのを防ぐ |
| 安定性ガード | 既存部屋に extraSocket を足すとき、再生成で既存ソケットが 1 つでも動いたり消えたりしたら取り消す（`addExtraSocketStable`） | 隣接直結で新部屋の出口が消える潜在バグを解消 |
| 出口なし拒否 | 扉・階段・その他進行手段が 1 つも無い Variant は配置しない（`hasFreeExit`） | 行き止まり確定の部屋を作らない |
| Legendary | 周囲に入らない Legendary は前室（4/3/2 m）+ 意図的 Seam で遠方（tryPlaceFree 広域、Variant 全段）へ。地図は「？」 | 105 件。Common〜Epic は Seam 禁止のまま |

## 残件（41 件）の内訳

| 分類 | 件数 | 説明 |
|---|---|---|
| 前室の末端が袋小路 | 16 | 前室（連鎖 2 つ目）の end の外に 2.6×3.2 は空いているが、部屋の最小 3.5×4 も前室も入らない |
| 扉の外は空いているが何も入らない | 5 | 部屋・小部屋・前室の全 Variant が入らない細い隙間（廊下の growToFill 未対応が主因） |
| frozen / 別フロア / Adapter に塞がれている | 8 | 見えている部屋に開口を足せない（不変条件どおり） |
| 施錠後に候補が全て壁へ戻った | 12 | 上のいずれかで施錠された後、prune（3/4）で全候補が消えた部屋（診断上は候補なしに見える） |

次の一手（未実装）: CorridorGenerator の `mainRect` 対応で隙間を減らす（SEAM-7）、frozen の緩和（SEAM-6、構築済み・未訪問・非可視の部屋）。

## 補足

- 施錠扉率 6.5% → 8.1% は分析の予測（8.3%）どおり。3/4 は壁へ戻すので見える施錠扉は 1 部屋あたり +0.5 本程度。
- 変更前の Seam は「開けた瞬間に座標遷移」なので踏破の続きがあったが、変更後の施錠は戻って別ルートへ進む。DFS 徒歩でも 100 部屋の踏破は全 seed で達成している（閉じ込めは起きていない）。

## レビュー修正後（2026-09-16、同じ 10 seed × 100 部屋）

| 指標 | 値 |
|---|---|
| WARN dead-end lock（施錠行き止まり） | 32（ノード 100 あたり 0.84 / 踏破 100 あたり 3.2） |
| 施錠され行き先の無い非扉開口（stairs / ramp / street / gate） | 0（修正前 8 seed で 48） |
| toJSON→fromJSON 整合（ソケット不一致 / 箱・照明不一致ノード） | 0 / 0（修正前は箱不一致が seed あたり 6〜11 部屋） |
| 決定論 / 部屋の重なり | OK / 0 |

- 床穴の判定・配置の乱数を `vr.fork('hole')` に分離し、`holeLocal` の有無で主乱数列の消費量が変わらないようにした（5 Generator）。`finalize` で holeLocal を設定した直後にレイアウトキャッシュを捨てる。乱数列が変わるので dead-end 件数は 41 → 32 になったが、これは配置結果の揺れで改善策ではない。
- `ensureNeighbors` の prune: 施錠され行き先の無い stairs / ramp / street / gate は常に `removedSockets` へ入れて壁へ戻す（扉は従来どおり 3/4）。
- 計測列を追加: `loadLayoutMismatch`（箱・照明）、`voidOpenings`。
