# 再現に使う技術の調査と採用

[01-reference-analysis.md](01-reference-analysis.md) で言語化した特徴を、プロの現場で使われている手法に当てはめた。
出典は調査時に開いたもの（または検索結果に出たもの）。WebGL2 / three.js r186 で動くことを前提に選んだ。

## 1. 平らな色面・少ない色数（全場面）

| 手法 | 中身 | 出典 | 採用 |
|---|---|---|---|
| 色彩設計（ノーマル色・影色） | アニメの色指定。物ごとに日なた・影の色を決め、照明で「掛け算」しない。Guilty Gear Xrd も影色 = 基本色 × 指定の色合い | Motomura, GDC 2015 (ggxrd.com/Motomura_Junya_GuiltyGearXrd.pdf) | **採用（中心）**。参考画像の色を物ごとに直接指定する |
| 照明の段落とし（トゥーン） | N·L × 影 × AO を段に切る。境目は `smoothstep` で 1 画素だけぼかす | Roystan (roystan.net/articles/toon-shader/)、UTS2 Shading Grade Map | **採用** |
| ソフトな段落とし | `tanh` で段の境目をなめらかにし、勾配の小さい所は柔らかく → 歩いても段が跳ねにくい | Winnemöller ほか, SIGGRAPH 2006 | 画面全体の後処理の段落としに採用（任意） |
| OKLab の色操作 | 明度・彩度・色相が分かれた知覚的に均一な色空間 | bottosson.github.io/posts/oklab/ | **採用**（陰の色の自動生成・色調整・映り込みの段落とし） |
| 異方性クワハラ | 構造テンソルで楕円の窓を作り、8 方向の分散が最小の平均を取る。細部をつぶして絵の具の塊にする。フレームごとでも時間的に安定 | Kyprianidis ほか, PG 2009／Acerola／Maxime Heckel | **任意**（淡色廊下・廊下で弱く） |
| SNN | クワハラより安い平坦化。BLUE PROTOCOL の背景の合成で使用 | CGWORLD CEDEC 2020 BLUE PROTOCOL | 不採用（クワハラで代用） |

## 2. ギザギザの光と影の境目（廊下・淡色廊下・プール・駅の水たまり）

| 手法 | 中身 | 出典 | 採用 |
|---|---|---|---|
| しきい値をずらす | 段のしきい値を頂点色・テクスチャでずらす（GGXrd・UTS2） | 同上 | ノイズ版で採用 |
| ワールド座標のノイズで境目をずらす | 画面座標のノイズは「シャワーのガラス越し」現象（模様が画面に張り付いて泳ぐ）になる。ワールド座標に固定したノイズを使う | Bénard ほか 2011 の総説、Braden Elwell の UE5 影シェーダー | **採用**（ねじった fbm で紙をちぎったような縁） |
| 影を調べる位置をずらす | 影の縁そのものをちぎる。面に沿って 2〜5 cm ずらす | 調査の合成 | **採用**（`shadowJitter`） |
| 影をタイル単位に丸める | プールの階段状の影。影を調べる位置をタイルの升目の中心に丸める。影のカメラは世界に固定（歩いても段が動かない） | 調査（BasicShadowMap + 低解像度の案）を発展 | **採用**（`shadowQuant`） |

## 3. 線（廊下・通路）

| 手法 | 中身 | 出典 | 採用 |
|---|---|---|---|
| 深度・法線・ID の段差で線を引く後処理 | Sobel / Roberts。物ごとの線の重み（BLUE PROTOCOL は頂点色で太さと部品 ID） | Roystan outline、Ameye、4Gamer CEDEC 2021 BLUE PROTOCOL | **採用**（2 枚目の出力に法線・ID・線の重み） |
| 浅い角度の誤検出を消す | 視線が面に浅いほど深度のしきい値を上げる（`1 + saturate((1-N·V-0.5)/0.5)·7`） | Roystan outline | **採用**（長い廊下の床・壁で必須） |
| 手描きのゆらぎ | 標本の位置をノイズでずらす。線をノイズで途切れさせる | Maxime Heckel Moebius | **採用**（ワールド座標のノイズで途切れ） |
| TAA を使わない | TAA は動くと線がにじむ。BLUE PROTOCOL も不採用 | 4Gamer CEDEC 2021 | **採用**（MSAA のみ） |

## 4. 霧・空気遠近（駅・通路・廊下）

| 手法 | 中身 | 出典 | 採用 |
|---|---|---|---|
| 解析的な高さの霧 | 密度 a·e^(−b·y) の積分を式で解く。視線の距離（view z ではなく長さ）で計算 | Inigo Quilez fog、Unreal Exponential Height Fog | **採用**（材質の中で計算） |
| 霧の色を空と同じ関数で | 霧の色を視線の向き（地平線→天頂）の関数にし、空のドームも同じ関数で描く → 継ぎ目が出ない | Unreal の Inscattering Color Cubemap、HDRP の Sky Color | **採用** |
| RGB で違う減衰 | 赤の減衰を大きくすると、中距離の物が白くなる前にシアンに寄る（駅の霧の色） | IQ fog | **採用**（`extinction`） |
| 最大の不透明度 | 一番遠い架線柱もかすかに残す | Unreal Fog Max Opacity | **採用** |
| 光源方向のにじみ | `pow(dot(rd, sunDir), 8)` で霧の色を光源の側だけ明るく | IQ fog | **採用**（`glow`） |
| 体積の霧（フロクセル） | 重い。three の例は WebGPU のみ | Hillaire 2020 ほか | 不採用 |

## 5. 濡れた床・水（駅・プール）

| 手法 | 中身 | 出典 | 採用 |
|---|---|---|---|
| 平面の鏡像（Reflector） | 鏡の位置のカメラでもう 1 回描く。平らな床 1 枚なら SSR より正確（画面外の上屋の灯りも映る）。霧も正しく入る | three Reflector、gamedev.net の比較 | **採用**（半分の解像度・MSAA なし） |
| 水たまりの形 | fbm のしきい値で不定形の縁（幅 0.02〜0.05 でくっきり） | Lagarde, Water drop 2b/3b | **採用** |
| 濡れの暗さ | 濡れると色が暗くつやが出る | Lagarde | **採用**（`wetDarken`） |
| 解析的な屈折 | 水面で屈折した視線を水路の箱と交差させ、その点のタイル目地と吸収 exp(−σL) を計算 → 屈折用の描画が要らない | Evan Wallace WebGL Water、Interior Mapping | **採用**（プールの水面） |
| 映り込みの段落とし | 映り込みの明度を 3〜4 段に、ゆがみも段に → ちぎれた色面の反射 | Ameye stylized water、調査の合成 | **採用** |
| コースティクス | ボロノイを時間で動かす | Cyanilux water breakdown | **採用** |

## 6. 光（駅の蛍光灯・プールの日差し）

| 手法 | 中身 | 出典 | 採用 |
|---|---|---|---|
| 光る板 + ブルーム | 放射の強さ 6〜15、しきい値 1.0 → 霧（≤1.0）はにじまず光だけにじむ | UnrealBloomPass | **採用**（自前の多段ぼかし） |
| 透過光（アニメの撮影処理） | 光を芯・本体・にじみの 3 層に分け、ぼかし量を変えて足す | animestyle.jp 透過光 | **採用**（加算の板） |
| ディフュージョン | ぼかした画像をスクリーン合成（Pro-Mist）。明るい霧が暗いシルエットの縁ににじむ = 新海誠作品の空気感 | Project SEKAI の合成、MHS3 CEDEC 2026 | **採用** |
| パラ・フレア | 画面に掛ける乗算・加算のグラデーション（撮影処理） | Project SEKAI、BLUE PROTOCOL | **採用** |
| 鋭い太陽の影 | PCF の半径 1、2048〜4096、場面に合わせた正射影の影カメラ。静止した場面なので影の更新は最初だけ | three r186（PCFSoft は廃止） | **採用** |
| 光の筋 | 天窓の桟から日の方向へ伸ばした加算の板（近く・床・真横でフェード） | Volumetric Light Beam | **採用** |

## 7. 合わせ込み（検証）

| 手法 | 中身 | 出典 | 採用 |
|---|---|---|---|
| カメラ合わせ | 消失点からカメラを求める（fSpy）。生成画像は消失点が一致しないことがあるので主な軸で合わせる | fSpy | 画面の重ね合わせで手で合わせる（視点ごとの位置・向き・画角を保存） |
| 重ね合わせ・差分・切り替え | 参考画像を画面に重ねる・差分・左右で切る | NVIDIA ꟻLIP | **採用**（`V` で切り替え） |
| 数値での比較 | 画素ごとの SSIM は絵には不向き。縮小して地域ごとの色差 ΔE（OKLab）、色の分布で比べる | 調査 | **採用**（撮影ツールが ΔE を出す） |
| カメラマッピング | 参考画像を視点から粗い形に投影する（『君の名は。』で検証された手法） | CGWORLD 君の名は。 | 不採用（その視点でしか合わず、歩けない。様式の再利用にならない） |

## 8. 採用した描画の流れ

```
[材質（MeshStandardMaterial を拡張）]
  色指定 → 模様（タイル目地・かすれ・白い斑・水たまり）
  → three の照明（平行光源の影 + 半球光 + 点光源）
  → 照明の倍率を段に丸める（境目はワールド座標のねじったノイズ）→ 段ごとの指定色
  → 映り込み（平面の鏡像。水たまりの中だけ / 水面は段落とし）
  → 霧（距離 + 高さ、RGB 別の減衰、空と同じ色の関数）
  出力: 色（HDR） + 情報（法線・ID・線の重み） + 深度   ※MSAA 4x

[後処理]
  1. （任意）異方性クワハラ
  2. 線（深度・法線・ID。浅い角度の補正・遠くで消す・ワールド座標のノイズで途切れ）
  3. ブルーム（光る板だけ）・ディフュージョン（スクリーン合成）
  4. パラ・フレア（画面のグラデーション）
  5. 色調整（OKLab の lift / gamma / gain・彩度・色相・色の偏り・明度の段落とし）・周辺減光・粒
  6. sRGB へ（ディザ）
```
