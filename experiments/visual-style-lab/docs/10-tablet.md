# タブレット（v2 のタブレットをそのまま持たせる）

ゲーム v2 のタブレット（`v2/client/tablet/`。v2/docs/tablet.md）を、見た目の検証ステージでも使えるようにした（2026-10-13）。
**v2 のファイルは変えず、複製もしない**（カメラ効果の VHS と同じく、v2 のファイルを直接読み込む）。

| 操作 | 中身 |
|---|---|
| Tab（スマホは右下の「端末」） | 出す・しまう |
| マウス（Pointer Lock 中） | 画面の上の指のカーソル。クリックで押す・ホイール・右クリックか Backspace で戻る |
| カメラ | クリックでシャッター・ホイールでズーム（1〜4 倍）。建築版では QR コードを撮ると読み取って次の場面へ移る（[11-qr.md](11-qr.md)） |
| 数字キー・Enter | 探索の番号（出している間は、場面の切り替えの数字キーはタブレットへ回す） |

## 機能ごとの扱い

| 機能 | このステージでは |
|---|---|
| ホーム・カメラ・ギャラリー・SNS・指のカーソル・出す / しまう動き | v2 のまま |
| 写真・SNS の保存先 | **ゲームと分ける**（`vsl.photos`・`vsl.sns`・端末の id `vsl.playerId`）。GitHub Pages ではゲーム（/pl-vs/v2/）と同じ公開元なので、名前を変えないと同じ保存先になる |
| 地図 | v2 の階の地図の代わりに、このステージの間取り図（M キーのミニマップと同じ図）。ホイール・＋−で拡大、ドラッグで動かす |
| 写真から移る（ギャラリー・SNS の「探索」） | 撮った場面（同じページの）と視点へ。場面が違えば読み直して、写真の視点に立つ |
| 探索（部屋の番号のダイアル） | 画面は残す。どの番号でも v2 の既存の表示「通信エラー：ROOM n は見つかりません」（4 桁未満は「ROOM n は見つかりません（4 桁以上）」）で移れない |
| 設定 | このステージの操作パネルを出す（隠していても） |
| ROOM の番号 | 場面の番号 × 1000 + 間取り図の場所の番号（例: 屋内プールの 12 番目の場所 = ROOM 3012） |
| 音 | このステージには音の仕組みが無いので、操作音・シャッターを WebAudio で短く合成 |

## 作り（src/tablet/）

- `LabTablet.ts`: v2 の `TabletController` は v2 のゲーム本体（`ClientGame`）を受け取るので、同じ形の受け皿（カメラ・ズーム・入力・
  持ち手の状態・音・写真を撮る・重ねて描く口・調整値）を作って渡す。地図・写真から移る・探索の働き（`TabletHooks`）もここ
- `env.ts`: v2 の `client/env.ts` の代わり。保存先の名前（`STORAGE_PREFIX`）だけ `vsl.` にする。`vite.config.ts` の `labEnv` が、
  v2 のファイルからの `../env.ts` をこれに差し替える（v2 のファイルは変えない）
- `LabAudio.ts`: 操作音・シャッターの合成
- 描き方: `Post.overlay`（合成の直後・カメラ効果の前に、深度を消して重ねる。v2 の ViewmodelPass と同じ置き場所）。カメラ効果（VHS）を
  入れているときは、タブレットにも走査線・にじみが掛かる（v2 と同じ）
- 写真: タブレットを消してもう 1 度描き、その場で画面を写す（v2 の写真の見た目は既定の clean = カメラ効果を掛けない）
- ズーム・写真から移った直後の画角: カメラ効果が入っていれば v2 の `CameraRig`（zoom・hold）へそのまま渡し、切っていれば `App.applyHeldView` で画角だけ掛ける
- タッチ: `core/Input.ts` を Pointer Events にした（タブレットの画面に当たった指はタブレットが先に受け取って止めるので、見回し・移動に回らない）

## 気を付けること

- v2 のタブレットの作り（`TabletController` が使うゲーム本体の項目）が変わると、ここが動かなくなることがある（受け皿は型を外して渡しているので、
  型の確かめでは見つからない）。変わったときは、このページを開いて Tab → カメラで撮る・ギャラリー・地図を確かめる
- タブレットを出していない間の描画は今までと同じ（31 視点とも元の版・2 つ目の組の値と同じ）
