# 参考画像からステージを作る手法（全体の流れ・工夫・使った技術）

imageboard の 14 枚（駅・プール・病院の廊下・淡色の廊下・校舎の間）を、歩き回れる 3D の場面にしたときの進め方を、
次に同じことをするときにそのまま使えるように書いたもの。
手順だけの短い版は Claude Code のスキル `.claude/skills/reference-stage/`（`/reference-stage` で呼べる）。

---

## 0. 全体の流れ

```
段階 0  参考画像を読む ………… 特徴を言葉と数値にする（色・明るさ・平らさ・境目・線・空気・カメラ）
段階 1  手法を選ぶ ……………… 特徴ごとに、プロの現場で使われている手法を調べて対応させる
段階 2  描き方の道具を作る …… 材質・後処理・霧・反射。動作確認の場面で全部試す
段階 3  比べる道具を作る ……… 参考画像と同じ寸法で描き、並べた画像・差の地図・輪郭の重なり・数値を出す
段階 4  場面を作る（視点ごと）… カメラ → 粗い形 → 色 → 光と影の形 → 空気 → 小物 → 歩けるように → 歩いて確かめる
段階 5  並行で作って見直す …… 1 場面 1 担当。統括が数値と画像で見直し、具体的に指摘して戻す
```

段階 4 の中は「前の段が合っていない所で次の段を頑張らない」が原則。カメラがずれたまま色を合わせると、
数値は下がっても絵が別物になる（今回のプールで起きた）。

## 1. 段階 0: 参考画像を読む（言語化）

### 1-1. 見る所

| 観点 | 問い | 今回の答えの例 |
|---|---|---|
| 構図 | 一点透視か二点透視か。消失点・地平線はどこか。目の高さは | 廊下は一点透視で消失点が中央より上（少し見下ろす）。駅は地平線が中央より下（少し見上げる） |
| 色 | 何色が何割か。彩度は。アクセントの色は | 緑みの青〜黄緑の狭い帯。アクセントは珊瑚色の扉・黄色の点字ブロックだけ |
| 明るさの段 | 面が平らな 1 色か、なめらかなグラデーションか。何段か | 廊下は 2〜3 段の平らな色面。駅はなめらか |
| 境目の形 | 光と影の境目はまっすぐか、ちぎれているか、階段状か | 廊下はちぎった紙。プールはタイル 1 枚単位の階段 |
| 線 | 輪郭線はあるか。色・太さ・どこにだけあるか | 物の外形と接地にだけ、暗い青緑（黒ではない） |
| 空気 | 奥が明るくなるか暗くなるか。霧の色は空と同じか | 駅は濃いシアンの霧が空と同じ色。廊下は奥が少し白む |
| 光源 | 何が光っているか。にじみ方は | 蛍光灯の板 + 柔らかいにじみ |
| 質感 | 反射・水・濡れ・タイル目地 | 水たまりは鏡、縁はくっきり。プールの水は 2〜3 段の色面の反射 |
| 小物 | 何が記号的に描かれているか | 掲示物 = 白い長方形に灰色のくねった線 |

### 1-2. 数値で測る（言葉だけにしない）

画像を読んだら、次の数を出す（`node tools/capture.mjs --analyze <場所 か 視点>`。OKLab で計算）。

| 数値 | 意味 | 使い道 |
|---|---|---|
| 平均明度 L・p5・p95 | 全体の明るさと幅 | 暗い場面（通路 0.34）か明るい場面（淡色 0.84）か |
| 平均彩度 C | 色の濃さ | 0.02〜0.06 しかない → 彩度を上げすぎない |
| 色相の中央値 | 色の偏り | 駅 205°（シアン）、廊下 120〜170°（セージ） |
| 平坦率 | 隣の画素との明度差が 0.01 未満の割合 | 0.85 超なら平らな面が多い（なめらかなグラデーションも平らに数えるので、上位 16 色と合わせて見る） |
| **上位 16 色の面積** | 5 bit に丸めた色の上位 16 色が占める割合 | 0.75 以上なら「色の指定で塗る」場面。0.5 未満ならグラデーション・模様が多い |
| k-means の 10 色 | 使われている色の表 | 材質の色の候補 |
| 行ごとの明度 | 上から下への明るさの変化 | 暗い天井の帯・明るい霧の帯などの構造 |

この数値で場面ごとの「描き方の型」を決めた。

| 型 | 判断の目安 | 今回（上位 16 色の面積） |
|---|---|---|
| 平らな色面（照明なしで面ごとに色を塗る） | 上位 16 色 0.6 以上・影がほとんど無い | 淡色の廊下 0.68・校舎の間 0.72 |
| 段落とし（照明で色の段を選ぶ） | 上位 16 色 0.75 以上・2〜4 段の光と影がある | 病院の廊下 0.80〜0.89 |
| 段落とし + 模様（タイル・水） | 上位 16 色は低い（模様で色数が増える）が、面は平ら | プール 0.22〜0.36 |
| 半写実（なめらかな光 + 霧 + 反射） | 上位 16 色 0.35〜0.55・グラデーションが多い | 霧の駅 0.37〜0.54 |

数値は目安。最後は画像を見て決める（プールは数値だけだと半写実に見える）。

### 1-3. 場所でまとめる

同じ場所を違う角度から描いた画像は、**1 つの歩ける空間の中の別の視点**にした（駅 4 枚・プール 4 枚・廊下 4 枚）。
こうすると「視点の間を歩く」ことができ、画像同士で矛盾する所を 1 つの空間でどう解くかを決める必要が出る（後述）。

## 2. 段階 1: 手法を選ぶ

特徴ごとに、ゲーム・アニメの現場の発表（GDC・CEDEC・SIGGRAPH）や技術記事を調べて対応させた（詳しくは [02-techniques.md](02-techniques.md)）。

| 参考画像の特徴 | 選んだ手法 | 出典の例 |
|---|---|---|
| 色数が少ない・色指定どおり | **色彩設計**: 物ごとに日なた・陰・暗部の色を参考画像から直接指定。照明は「どの色を塗るか」を選ぶだけ | Guilty Gear Xrd（GDC 2015）、アニメの色指定 |
| ちぎれた境目 | 段のしきい値を**ワールド座標のノイズ**でずらす（画面座標のノイズは歩くと模様が泳ぐ） | Bénard ほかの総説、UTS2 |
| 階段状の影 | 影を調べる位置をタイルの升目の中心に丸める | （調査の案を発展） |
| 少ない線 | 深度・法線・ID の段差から線を引く後処理。浅い角度の補正 | Roystan、BLUE PROTOCOL（CEDEC 2021） |
| 奥が明るい | 距離と高さの霧。霧の色 = 空の色（同じ関数） | Inigo Quilez、Unreal Height Fog |
| 濡れた床・水 | 平面の鏡像 + ノイズの水たまり。水は解析的な屈折 | Lagarde、Evan Wallace |
| 光のにじみ・空気感 | ブルーム + ディフュージョン + パラ・フレア | Project SEKAI の撮影処理、新海誠作品 |
| 絵の具の塊 | 異方性クワハラ（任意） | Kyprianidis 2009 |

**採用しなかった物と理由**（次も同じ判断でよい）:

- **カメラマッピング**（参考画像をその視点から形に投影する）: その視点でしか合わず、歩けず、様式として再利用できない
- **画面空間の反射（SSR）**: 画面外の物（頭上の蛍光灯）が映らない。平らな床 1 枚なら平面の鏡像が正確
- **体積の霧**: 重い。解析的な霧で足りる
- **TAA**: 動くと線がにじむ（BLUE PROTOCOL も不採用）

## 3. 段階 2: 描き方の道具を作る

場面を作り始める前に、描き方の部品を全部作り、**動作確認の場面（`src/scenes/test.ts`）で 1 つずつ試した**。
ここで「影を升目に丸める」が実は効いていない不具合（three のシェーダーの include が後で展開されるため置き換えが空振りしていた）を見つけた。
場面を作る担当が見つける前に直せたので、試す場面は必ず作る。

### 3-1. 色彩設計の材質（`src/render/StyleMaterial.ts`）

three の MeshStandardMaterial に次を足したもの。

1. 照明の計算はそのまま three に任せる（平行光源・影・半球光・点光源）
2. 照明の結果を「色指定に対する倍率 F」に直す（F = 1 なら色指定のまま。平行光源の強さ π で真正面から当たると F = 1）
3. F を段に切る: `hi > color > shade > dark`。各段の色は**参考画像から拾った色をそのまま指定**
4. 段のしきい値を、ワールド座標のねじったノイズ（fbm を fbm でずらした物）で上下させる → ちぎった紙のような縁。ワールド座標なので歩いても泳がない
5. 模様: タイル目地（面の向きに合わせた座標）・壁の傷（升目ごとの短い線）・白い斑（ねじったノイズのしきい値。高さと位置で増減）・水たまり
6. 影の位置を丸める（`shadowQuant`）・ずらす（`shadowJitter`）。1 つ目の平行光源の影を調べる座標を、面に沿って升目の中心へ丸める
7. 霧（後述）と、後処理用の情報（法線・ID・線の重み）を 2 枚目の出力へ

**デザインの工夫**: 陰の色は「暗くする」ではなく「色相をずらす」。クリームの壁の陰はセージ寄り、白いタイルの陰は青緑寄り。
OKLab で明度を下げつつ色相を回す既定値（`toon.shade: [明度の倍率, 彩度の倍率, 色相の回転]`）を場面ごとに決め、拾えた色は直接書く。

### 3-2. 平らな場面の材質（`src/render/PaintMaterial.ts`）

ほとんど影の無い場面（淡色の廊下・校舎の間）では、照明を使わず**面の向き（±X・±Y・±Z）ごとに色を直接塗る**方が速く正確だった。
腰壁（高さで色を変える・縁はノイズでちぎる）と、塗りの層（ねじったノイズのしきい値 + 上から見た分布の絵で「どこに白い斑が出るか」を手で決める）を重ねる。

### 3-3. 描いた影・光（`src/render/Decal.ts`・`Builder.shadowCaster`）

光源では作れない「絵の都合の影」（廊下の天井下の影の帯・床の光の四角・幅木の帯）は、縁がちぎれる貼り絵で描く。
BLUE PROTOCOL の背景が「物理的に無い影も描き足す」のと同じ考え。プールでは影だけを落とす見えない板で、参考画像の影の形を作った。

### 3-4. 後処理（`src/render/Post.ts`）

```
場面（色 + 情報 + 深度。MSAA 4x）→ クワハラ（任意）→ ブルーム・ディフュージョン
→ 合成: 線 → にじみ → 露出・トーン → パラ / フレア → OKLab の色調整 → 周辺減光・粒 → sRGB
→（カメラ効果がオンなら）レンズ → sRGB → ビデオ
```

- **線**: 深度は中心と周り 8 つ、法線と ID は**向かい合う 2 つの組**で比べる。MSAA で縁の画素の法線が平均されるので、中心と比べると長い辺が点線になった（担当の報告で発見）
- **浅い角度の補正**: 視線が面に浅いほど深度のしきい値を上げる（長い廊下の床・壁に線が出ないように）
- **線はワールド座標のノイズで途切れさせる**（手描きの線の切れ）。遠くで消す
- **色調整は OKLab**: 明度の lift / gamma / gain、彩度、色相、色の偏り、明度の段落とし（tanh で柔らかく）

### 3-5. 霧と空

- 距離と高さの霧を材質の中で計算する（視線の長さで。three の FogExp2 は view z なので首を振ると変わる）
- **霧の色を視線の向きの関数にして、空のドームも同じ関数で塗る** → 霧に溶けた物と空の継ぎ目が出ない
- **RGB ごとの減衰**: 赤を大きくすると、中距離の物が白くなる前にシアンに寄る（駅の霧の色）

### 3-6. 反射と水

- 平面の鏡像（`PlanarReflector`）: 鏡の位置のカメラでもう 1 回描く。斜めの近クリップ面で鏡の下を切る。半分の解像度
- 水たまり: ノイズのしきい値の形の中だけ映す。縁はくっきり
- プールの水（場面の材質）: 屈折した視線で水底の高さの升目をたどり、その点のタイル目地を描き、深さで青緑へ吸収。屈折用の描画が要らない
- 映り込みを明るさの段に丸める・明るい物だけ映す（`reflection.posterize` / `key`）→ 生成画像の「ちぎれた色面の反射」

## 4. 段階 3: 比べる道具を作る（いちばん効いた）

`tools/capture.mjs`（ヘッドレスの Chrome を GPU 付きで動かす。依存なしの Node だけ）。

| 出力 | 何が分かるか |
|---|---|
| `<view>.png` | 参考画像と同じ 1456×816 の描画 |
| `<view>-cmp.png` | 左に描画・右に参考画像。目で比べる |
| `<view>-diff.png` | 差の地図。赤 = 描画が明るい、青 = 暗い、緑 = 色みの差。**どこを直すか**が一目で分かる |
| `<view>-edges.png` | 輪郭の重なり。参考 = 赤、描画 = 水色、重なり = 白。**カメラと形のずれ**が一目で分かる |
| ΔE・ΔL・彩度 | OKLab の色差（×100）・明るさの差・彩度。全体と地域（`--grid 8x4`）ごと |
| 構図 F | 輪郭の一致（×100）。P = 余計な線の少なさ、R = 足りない物の少なさ |
| `--sample` / `--sample-both` | 参考画像（と描画）の色を画素の位置で拾う |
| `--params` | 見た目の値を一時的に上書き（ファイルを書き換えずに試す） |
| `--perf` | 1 フレームの重さ |
| `--sheet` | 全視点の比較を 1 枚に |

**数値の目安**（今回の結果から）:

| 指標 | よく合っている | 構図・色調は合っている | まだ別物 |
|---|---|---|---|
| ΔE | 2〜3 | 4〜5.5 | 7 以上 |
| 構図 F | 70 以上 | 60〜70 | 55 未満 |

ΔE だけでは「柱が 1 本足りない」「全体が数 px ずれている」を見逃す（暗い部分が多い絵は色が合えば下がる）。
構図 F（輪郭）は色を見ないので、両方で見る。最後は必ず `-cmp.png` を目で見る。

ブラウザでは V キーで参考画像を重ねる・左右で切る・差分で見られる。

## 5. 段階 4: 場面を作る（視点ごとの手順）

### 5-1. カメラを解く

1. 参考画像で、奥へ向かう水平な線（床と壁の境目・天井の縁・線路）を 2 本以上なぞり、消失点の画素を出す
2. 既知の寸法から縦の画角と目の高さを決める（扉 2.0〜2.1 m・天井 2.5〜3 m・目 1.5〜1.6 m・ホームの高さ 1.1 m・タイル 25 cm など）
3. `solveFromVanishingPoint(vp, fov)` で yaw と pitch を出す（`src/core/ViewCam.ts`）
4. `new ViewCam(eye, yaw, pitch, fov)` を作り、ViewDef に `cam.def()` を入れる
5. **合格**: `-edges.png` で床と壁の境目・扉・柱の縁が白く重なる。構図 F が 60 を超える

今回の例: 淡色の廊下は消失点 (762, 436)・目の高さ 1.25 m・焦点距離 1000 画素（縦の画角 44.4°）。
最初に推測した 62° のまま進めた版（ΔE 7.1）から、解き直しただけで形が一気に合った。

### 5-2. 粗い形を画素から逆算する

`cam.hit(x, y, 'x' | 'y' | 'z', v)` で「画像のこの画素に見える、この面（x = v など）の上の点」を求めて、壁・柱・扉・物を置く。
掲示物・窓は `cam.rectOn(...)` で外接矩形から面の上の長方形にする。置いたら `cam.proj(p)` で画像のどこに出るかを確かめる。
**合格**: 主な縁が `-edges.png` で白く重なる。構図 F が 70 前後。

### 5-3. 色を置く

1. `--sample <view> x,y ...` で各面の色を拾う（日なたの面・陰の面・暗部・アクセント）
2. 材質の `color` / `shade` / `dark` / `hi` にそのまま書く（平らな場面は面の向きごとに）
3. `-diff.png` の赤・青の塊から直す。地域の ΔE が大きい所から
**合格**: 平らな面の色差が ΔE 1 未満（`--sample-both` で確かめる）

### 5-4. 光と影の形

- 光の向きを決めて、**どの面がどの段になるか**を参考画像に合わせる（廊下: 半球光で面の向き、真上に近い平行光で床と上面だけ日なた）
- 光源で作れない形は描く（貼り絵・影だけの板）。境目のちぎれ方はノイズの強さと大きさで合わせる
- 曇りの日の明るさは「空がどれだけ見えるか」で決まる（駅: 屋根の長方形が空を隠す割合を式で求めた）

### 5-5. 空気と後処理

霧の濃さ・高さ・色（地平線・天頂）、線の色と太さと途切れ、ブルーム・ディフュージョン、OKLab の色調整を合わせる。
視点ごとに色調が違う画像は、視点の `style`（と歩くときの `styleZones`）で場所ごとに変える。

### 5-6. 小物と模様

記号的な小物（掲示物・スイッチ・カート・椅子）を足す。掲示物は 1 枚のキャンバスにまとめて描く（白い紙・灰色のくねった線・赤い印）。
椅子は「1 席ずつの成形の座面と背」まで作ると「黒い板の塊」に見えなくなる（駅で効いた）。

### 5-7. 歩けるようにする

当たり判定（床の上面が歩ける高さ・壁は押し出し）、視点の間を歩ける道、場所ごとの見た目（`styleZones`）。
影の地図は動かない場面なら毎フレーム描かない（`staticShadows`。4096 の影で約 6 ms 軽くなる）。

### 5-8. 参考画像の無い所を歩いて確かめる

参考画像の視点の間・外を歩いて、**継ぎ目・箱の縁・模様の泳ぎ・縞**が出ないかを見る。今回見つけた例:
- 屋根の下の霧を暗くする箱の縁が、外から見ると半透明の箱に見えた（縁を 1〜2 m でぼかして解決）
- 草の細い縦線の模様が雨やバーコードに見えた（0.2〜0.5 m の柔らかい塊に変えて解決）

## 6. 段階 5: 並行で作って見直す

### 6-1. 分け方

- 1 場面を 1 担当（エージェント）に。担当は自分の場面のファイルだけを触る
- 描き方の道具（`src/render`・`src/core`・道具）は統括だけが触る。足りない物は担当が場面の中で作るか、報告で依頼する
- 依頼が来たら統括が道具に入れて、全担当に知らせる（今回: 毎フレームの準備の口・区域ごとの見た目・照り返し・影だけの板・映り込みにだけ出す層・差の地図・`--params`）

### 6-2. 担当への指示に必ず入れたこと

- 目的（参考画像を 100% 再現・歩ける）と、場面の言語化（何が写っているか）
- 読む資料と道具の使い方、所有するファイル、触らないファイル
- 合わせ込みの手順と「20 回以上撮って直す」「似ているで止めない」
- 歩けること・重さの上限・報告の形（数値・正直な評価・比較画像の場所・依頼）

### 6-3. 見直しの仕方

担当の報告は鵜呑みにせず、**統括が自分で撮り直して比較画像を見る**。指摘は具体的に:

> 「pool-3: 参考画像では左の柱が x≈200〜490、右が x≈1000〜1280。描画は左 70〜480・右 840〜1280 で太すぎる」

のように、**画素の位置 + 参考画像では何 + 描画では何**で書く。抽象的な「もっと似せて」では直らない。
今回は場面ごとに 2〜4 回戻した。プールは 1 回目の担当の方法が行き詰まったので、新しい担当に引き継いだ。

## 7. 守った決めごと

1. **参考画像の画素を自動で場面へ写さない**（カメラマッピング禁止）。手で測った値（画素の位置・拾った色）を書くのは可。
   駅の担当が水たまりの形を参考画像から自動で焼いていたので、ノイズと手で置いた形に作り直させた
2. **数値のために絵を壊さない**。自動の値探しで ΔE を下げたら明暗が平らになった（プール）。数値は道しるべで、最後は目で決める
3. **歩いても壊れない**: ノイズはワールド座標、影のカメラは世界に固定、見えない箱の縁を出さない
4. **重さ**: 1456×816 で 1 フレーム 8 ms 以下

## 8. 工夫のまとめ

### 技術

| 工夫 | 効果 |
|---|---|
| 照明を「色を選ぶ」ためだけに使う | 参考画像の色がそのまま出る。照明の強さを細かく合わせなくてよい |
| ワールド座標のねじったノイズで境目をずらす | ちぎった紙の縁。歩いても泳がない |
| 影の座標を升目に丸める | タイル 1 枚単位の階段状の影 |
| 法線・ID を向かい合う組で比べる | MSAA でも線が点線にならない |
| 霧と空を同じ関数で | 継ぎ目の無い空気遠近 |
| RGB ごとの減衰 | 中距離がシアンに寄る霧 |
| 空の見える割合で明るさ（駅） | 影の地図なしで曇りの日の柔らかい光 |
| 解析的な屈折（プール） | 水底のタイルが屈折して見える。描画は 1 回 |
| 映り込みにだけ出す層（layer 2） | 画面には無いが水面には映る屋根の続き |
| 比べる道具（差の地図・輪郭・数値） | 「どこを・どれだけ」直すかが分かる |

### デザイン

| 工夫 | 効果 |
|---|---|
| 陰の色は色相をずらす（クリーム → セージ、白 → 青緑） | 平らでも単調にならない、アニメの色指定の質感 |
| 線は黒でなく暗い青緑、少なく、途切れさせる | 生成画像の「描いた」感じ |
| 奥ほど明るく淡く | 奥行きと空気（リミナル感の中心） |
| 小物は記号に（紙 = 白い長方形 + くねった線） | 情報量を抑えて画面が平らに保たれる |
| 描いた影を足す | 光源だけでは出ない「絵の都合の影」 |
| 場所ごとに色調を変える（視点の style・区域） | 同じ駅でも画像ごとの空気の違いを残す |

## 9. うまくいかなかったこと → 次は最初からこうする

| 起きたこと | 次からの対策（道具は入れ済み） |
|---|---|
| カメラの画角を推測で始め、後で直した（淡色 ΔE 7.1 → 2.4） | 段階 4 の最初にカメラを解く。`ViewCam`・`solveFromVanishingPoint` を最初から使う |
| ΔE は下がったのに構図が別物（プール） | 構図 F と `-edges.png` を合格の条件にする（F 60 未満で色合わせに進まない） |
| 3 つの担当が同じ道具（画素 ↔ 座標）を別々に書いた | `src/core/ViewCam.ts` に 1 つにした |
| 塗りの材質・貼り絵が場面の中にあった | `src/render/PaintMaterial.ts`・`Decal.ts` に移した |
| 道具の不具合（影の丸めが効かない）を場面作りの途中で見つけた | 段階 2 の動作確認の場面で、部品を 1 つずつ数値と画像で確かめる |
| 自動の値探しで明暗が平らに | 自動調整は色だけ。形・明暗の構造は手で。必ず画像を見て決める |
| 参考画像を自動で写す手法が紛れ込んだ（駅の水たまり） | 担当への指示の最初に禁止を書く |
| 参考画像の無い所の継ぎ目（霧の箱・草の縞） | 段階 4 の最後に「視点の間を歩く撮影」を入れる |
| 生成 AI の画像は 1 枚ごとに形が矛盾する（プールの柱の位置） | 1 つの空間にまとめるとき、どの画像を優先するかを先に決める。合わない画像は区画を分ける |
| 担当の文脈が長くなると改善が鈍る | 2 回戻しても数値が動かなければ、新しい担当に引き継ぐ（指摘をまとめて渡す） |

## 10. 次に使うとき

1. 参考画像を `public/refs/<場所>-<番号>.jpg`（1456×816 推奨。違う比率なら `REF_W` / `REF_H` を合わせる）に置く

4. 段階 0 → 5 の順に進める。各段の合格の条件を満たしてから次へ
