# Spark 検証サンプル

見た目は 3D Gaussian Splatting（Spark）、ゲームの処理は透明な箱、という分け方がブラウザで成立するかを確かめるためのサンプルです。撮影データが無くても試せるよう、部屋と小物はコードで生成した仮のスプラットを使っています。

| フォルダ | 内容 |
|---|---|
| `01-two-rooms/` | 検証1：部屋2つとドア1枚 |
| `02-mesh-room-splat-props/` | 検証2：メッシュの部屋とスプラットの小物 |
| `common/` | 共通の部品（移動と当たり判定、画面表示、仮素材の生成） |

使用ライブラリ：three.js 0.180.0 / Spark 2.3.1 / lil-gui 0.20.0（CDNから読み込み、バージョン固定）

## 動かし方

ファイルを直接開くと動きません。このフォルダでローカルサーバーを起動してください。

```
npx serve .
# または
python3 -m http.server 8000
```

pro_Liminal のリポジトリ直下からなら `python3 -m http.server 8000 --directory experiments/spark-samples` です（`.claude/launch.json` の `spark-samples` も同じ内容）。

表示されたアドレス（例：`http://localhost:8000`）を開くと、2つのサンプルへのリンクがあります。

スマホで試す場合は、PCと同じネットワークにつなぎ、PCのIPアドレス（例：`http://192.168.0.10:8000`）を開きます。

## 操作

| | PC | スマホ |
|---|---|---|
| 移動 | WASD（Shiftで走る） | 画面の左半分をドラッグ |
| 視点 | クリックしてマウス | 画面の右半分をドラッグ |
| ドア（検証1） | E | 近づくと出るボタン |
| 補正の比較（検証2） | C | 設定パネル |
| 設定 | Escでカーソルを戻し、右上のパネル | 右上のパネル |

左上のパネルに、FPS、描画中の粒の数、メモリ、操作の記録が表示されます。

## URLで指定できる値

| 値 | 対象 | 意味 |
|---|---|---|
| `?roomA=xxx.spz` `?roomB=xxx.spz` | 検証1 | 部屋を撮影データに差し替える |
| `?spacing=0.06` | 検証1 | 仮の部屋の粒の間隔（m）。大きいほど粒が減って軽い。初期値 0.03 |
| `?latency=1500` | 検証1 | 読み込みに疑似的な遅延（ミリ秒）を足す |
| `?density=4` | 検証2 | 仮の小物の粒の密度。初期値 1 |
| `?copies=20` | 検証2 | 最初からテレビを複製して置く |
| `?capture=1` | 両方 | 画面を画像として取り出せるようにする（少し重くなる） |

## 検証1：部屋2つとドア1枚

部屋Aからドアを開けて部屋Bへ進みます。ドアに近づくと隣の部屋を読み込み、離れてドアが閉まると破棄します。

確かめること

- 透明な箱の当たり判定で、壁やドアを自然に通れないか（設定の「当たり判定を表示」で箱が見えます）
- ドアの開閉の見た目と、開いた先に隣の部屋がきちんと見えるか
- **隣の部屋を読み込んだ瞬間にカクつかないか**（下の「分かっていること」を参照）
- 「疑似的な読み込み遅延」を大きくしたとき、ドアが読み込みを待ってから開くか
- 「メモリの検証」で読み込みと破棄を繰り返したあと、テクスチャ数やヒープが増え続けないか

## 検証2：メッシュの部屋とスプラットの小物

照明を焼き込んだ想定のメッシュの部屋に、4つの小物を置いています。

| 小物 | 確かめる観点 |
|---|---|
| 観葉植物 | 柔らかく形の複雑なもの |
| ブラウン管テレビ | 硬いもの。メッシュの棚の上に載せている |
| ぬいぐるみ | 半透明のガラスケースの中 |
| 段ボール | ガラスの手前。描画順の問題が出やすい位置 |

確かめること

- 小物が浮いて見えないか。Cキーで色合わせと影をまとめて切り替えて比べる
- 照明の種類を変えたとき、「照明の色に合わせる」で小物が馴染むか
- 接地の影（床に敷いたデカール）の濃さと大きさ
- ガラス越しの見え方。「ガラスを小物より後に描く」を切り替えると、段ボールにガラスが重なる問題が確認できる
- 「テレビの複製数」を増やしたときのFPS（データは1つを共有している）
- 小物を近くで見たときのぼやけ具合

## 撮影データへの差し替え

設定パネルの各「素材」フォルダにある「自分のファイルを読み込む」から、`.spz` `.ply` `.splat` `.ksplat` `.sog` などを選べます。

撮影データの多くは上下が逆の座標系なので、「上下を反転（撮影データ用）」は初期状態でオンにしています。位置・向き・大きさを調整して当たり判定の箱（または置き場所）に合わせ、「位置合わせの値をコピー」で値を控えておくと、コードの `transform` にそのまま貼れます。

## 分かっていること

**共有データの破棄に注意。** Spark 2.3.1 の `SplatMesh.dispose()` は、その SplatMesh が使っている `PackedSplats` も破棄します。同じデータを複数の SplatMesh で使い回す（同じ小物を複製して置く）場合、1つを破棄すると他も壊れます。検証2の `disposeSharingMesh()` では、参照を外してから破棄しています。

**アンチエイリアスは切る。** Spark の推奨に従い、`WebGLRenderer({ antialias: false })` にしています。スプラットには効果がなく、重くなるだけです。

**半透明メッシュとの重なり。** スプラットは深度を書き込まない半透明の描画です。そのため、半透明のメッシュ（ガラスなど）とスプラットが重なると、描画順によって手前と奥が逆に見えることがあります。床の影のデカールはスプラットより先に、ガラスは後に描くよう `renderOrder` で指定しています。

**オブジェクトを後から追加したときのカクつき。** GPUの無いソフトウェア描画の環境で試したところ、描画が始まった後にスプラットのオブジェクトを追加すると、反映まで数十秒かかり、その間フレームレートが大きく落ちました。GPU のある Mac（Apple M5）で測ると、追加した直後の描画は重くならず（`renderer.render` は 1 回 20ms 未満）、止まるのは仮の部屋を JavaScript で生成している間だけでした（14.9 万粒で約 20ms、`?spacing=0.06` の 3.7 万粒で約 6ms）。撮影データ（`.spz`）は Spark が別のスレッドで展開するので、読み込み中に止まるのは 1〜2ms です。スマホでは仮の部屋の生成が数倍遅くなるはずなので、カクつきが気になったら `?spacing=0.06` と比べるか、撮影データに差し替えて確かめてください。

## 制限

- 当たり判定は床面上の簡易的なもので、段差やジャンプはありません
- ドアは回転途中だけ当たり判定を外しています
- 仮の素材はあくまで検証用で、写実的ではありません
- JSヒープの値は Chrome 系のブラウザでのみ表示されます。Safari では Web インスペクタのタイムラインで確認してください

## 検証の状況

2026-10-05 に Mac（Apple M5・Chrome 系のブラウザ・解像度の倍率 1.5）で、両方とも一通り動作を確認しました。FPS の 120 は画面の更新の上限です。

- 検証1：部屋A・Bともに 14.9 万粒、両方表示して 120FPS。ドアまで 3.0m で部屋Bを読み込み、4.0m 離れてドアが閉じていれば破棄する。閉じたドア・壁・仕切り壁で止まり、開いたドアや開口部の端では横に逸れて通れる。疑似的な遅延を入れるとドアは読み込みを待ってから開き、読み込み中に離れると読み込み後に破棄する。メモリの検証は 20 回×3 でテクスチャ差 +0、ヒープ差は数 MB の上下で増え続けない。`?roomB=` で撮影データ（.spz）に差し替えても動く。スマホ幅の表示（タッチ用の案内・ドアのボタン）も確認
- 検証2：小物4つで 4.7 万粒・120FPS。テレビの複製 27 個（40 万粒）でも 120FPS で、テクスチャは増えない（データを共有できている）。複製を消しても元のテレビは壊れない。C キーの比較、照明の種類、ガラスの描画順、深度書き込み、密度の変更（複製を残したまま作り直し）が動く。メモリの検証は 30 回×3 でテクスチャ差 +0、ヒープは GC で戻る。「自分のファイルを読み込む」で撮影データ（.spz）を読み込むと、上下反転の初期値のまま正しい向きで立つ（大きさは合わせる必要がある）
- 計測の確かさ：「GPU資源」のテクスチャ数は Spark の粒のデータも数えている（表示すると +1、`dispose()` で −1、外すだけだと残る）ので、メモリの検証の「テクスチャ差」で漏れを見つけられる
- 未確認：実機のスマホ（iPhone・Android）での動作と FPS、Safari での動作
