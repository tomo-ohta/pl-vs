# 参考画像から歩けるステージを作る

参考画像を見て測った値（画素の位置・拾った色）で形と色を決め、色彩設計の材質と後処理で絵の様式を作り、
参考画像と同じ寸法で撮って数値と画像で比べながら直す手法。2026-10-06 に imageboard の 14 枚で使い、
平らな色面の場面で ΔE 2.4〜2.8・構図 F 72〜78 まで合った（詳しい経緯・理由・工夫は `experiments/visual-style-lab/docs/05-method.md`）。

## 手順（各段の「合格」を満たしてから次へ）

### 段階 0. 参考画像を読む

1. 全部の画像を開いて見る。場所ごとにまとめる（同じ場所の別視点は 1 つの歩ける空間の別の視点にする）
2. `node tools/capture.mjs --analyze <場所>` で数値を出す（明度・彩度・色相・平坦率・上位 16 色・10 色の表・行ごとの明度）
3. [reference/checklist.md](reference/checklist.md) の「読む観点」で言語化し、`docs/` に書く（構図・色・明るさの段・境目の形・線・空気・光源・質感・小物・カメラ）
4. 描き方の型を決める: 平らな色面（`PaintMaterial`）/ 段落とし（`StyleMaterial`）/ 段落とし + 模様 / 半写実（`toon: 0` + 霧 + 反射）
5. **合格**: 特徴の表と型が書けていて、利用者に見せられる

### 段階 1. 手法を選ぶ

特徴ごとに [reference/techniques.md](reference/techniques.md) の対応表から選ぶ。表に無い特徴だけ調べる（GDC・CEDEC・SIGGRAPH・技術記事）。
**採用しない物**: カメラマッピング（参考画像の画素を自動で場面に写す）・SSR・体積の霧・TAA。

### 段階 1.5. 間取り図を作る（建築版。歩き回っても自然にする）

参考画像の視点の外まで自然にするなら、作る前に「この場所が現実にあったらどういう建物・敷地か」を間取り図にする
（詳しい手順・優先順位・確かめ方は `experiments/visual-style-lab/docs/06-architecture.md`）。

1. 現実の類型を調べる（建物の種類・寸法・法規・部屋の並びの根拠）
2. 視点ごとに写っている物・写っていない方向を書く（`ViewCam` で画素 → 座標）
3. 参考画像同士の矛盾を解く（区画を分けてそれぞれの画像を優先。現実離れした所は理由を記録）
4. `FloorPlan`（`src/arch/plan.ts`）を書いて `SceneDef.plan` に入れる。道順（tour）は 10 か所以上
5. `--page arch.html --plan <場所>` で画角に参考画像に無い物が入らないかを確かめる（曲がり・閉じた扉・霧で隠す）
6. 図のとおりに作る（`src/arch/kit.ts`）。部屋の種類ごとに置く物の決まりを作り、写っていない所も同じ作り込みに
7. **合格**: 元の版との比べ（`--baseline tools/baseline-v1.json`。ΔE +0.5・構図 F −3 以内）・図との重ね（`-plan-top.png`）・
   歩いて行けるか（`--reach`）・写っていない所の撮影（`--tour`）・重さ

### 段階 1.6. 写っていない所を参考画像の視点と同じ仕上がりにする

建築版で建物はつながっても、写っていない所は形・材質・模様・光が素っ気なくなりやすい（詳しくは `experiments/visual-style-lab/docs/07-unseen-quality.md`）。

1. 参考画像の語彙を書く: 大（柱型・梁・枠・段）・中（器具・掲示・配管・家具）・小（紙・染み・目地・ちぎれ）の密度と、光の言葉
2. `--page arch.html --quality <場所>` で、参考画像・視点の描画・道順・無作為の場所を同じ数値（細部・形・明暗・幅・平ら・色差）で比べ、弱い所を見つける
3. 部屋の種類・面の種類ごとの決まりで直す（撮られる所だけを直さない）。光は本物の器具の下に `ctx.addLamp`（照らす箱 = 部屋の内側）
4. **合格**: 道順と無作為（種を変えて 2〜3 回）の中央値が視点の描画の 0.85〜1.35 倍、印の付く撮影が 2 割程度まで。
   視点の比べ・歩けるか・重さはそのまま合格。最後は参考画像と並べて目で決める（数値を意味の無い粒で上げない）

### 段階 2. 描き方の道具を確かめる

新しい道具を足したら、`src/scenes/test.ts` のような確認の場面で 1 つずつ撮って効いているかを見る（今回は「影の升目」が効いていない不具合をここで見つけた）。
**合格**: 使う部品が全部、確認の場面で意図どおりに見える。

### 段階 3. 比べる道具

`node tools/capture.mjs <視点>` が `<視点>.png`・`-cmp.png`（並べた画像）・`-diff.png`（差の地図）・`-edges.png`（輪郭の重なり）・ΔE・構図 F を出すことを確かめる。

### 段階 4. 視点ごとに合わせる

| 段 | やること | 合格 |
|---|---|---|
| 4-1 カメラ | 奥へ向かう水平な線 2 本以上から消失点 → `solveFromVanishingPoint(vp, fov)`。画角と目の高さは既知の寸法（扉 2.0〜2.1 m・天井 2.5〜3 m・目 1.5〜1.6 m・タイル 20〜30 cm）から | `-edges.png` で床と壁の境目・扉・柱が白く重なる。構図 F ≥ 60 |
| 4-2 粗い形 | `cam.hit(x, y, axis, v)`・`cam.rectOn(...)` で画素から位置と寸法を逆算して置く。`cam.proj(p)` で確かめる | 構図 F ≥ 70（模様・植物の多い絵は ≥ 65） |
| 4-3 色 | `--sample` で拾った色を材質の `color` / `shade` / `dark` / `hi`（平らな場面は面ごと）に直接書く。`-diff.png` の塊から直す | 平らな面で `--sample-both` の差がほぼ無い。地域 ΔE の大きい所が「形の違い」だけになる |
| 4-4 光と影の形 | どの面がどの段か（光の向き）を合わせる。光源で作れない形は `Decal`・`b.shadowCaster`。境目のちぎれはノイズの強さ・大きさで | `-diff.png` に大きな赤・青の面が残らない |
| 4-5 空気・後処理 | 霧（濃さ・高さ・地平線と天頂の色・RGB の減衰）・線・にじみ・ディフュージョン・パラ / フレア・OKLab の色調整。画像ごとの色調は視点の `style` と `styleZones` | ΔE（全体）が平らな場面で ≤ 3、半写実で ≤ 5 を目安に |
| 4-6 小物・模様 | 記号的な小物、掲示物は 1 枚のキャンバスにまとめて描く | 比較画像で「足りない物」が無い |
| 4-7 歩ける | 当たり判定・視点の間の道・`styleZones`・動かない場面は `staticShadows` | 全視点へ歩いて行ける |
| 4-8 歩いて確かめる | 参考画像の視点の間・外を撮る（`--params` やブラウザで） | 継ぎ目・箱の縁・模様の泳ぎ・縞・急な色の切り替わりが無い。1456×816 で 8 ms 以下（`--perf`） |

数値は道しるべ。**毎回 `-cmp.png` を目で見て**、形・明暗の構造・質感を確かめる。

### 段階 5. 並行で作って見直す（場面が 2 つ以上のとき）

1. 1 場面を 1 担当（エージェント）に。指示は [reference/agent-brief.md](reference/agent-brief.md) の雛形で（目的・言語化・所有ファイル・禁止事項・手順・合格・報告の形）
2. 描き方の道具は統括だけが触る。担当の依頼は統括が入れて全担当に知らせる
3. 報告が来たら**統括が自分で撮り直して**比較画像を見る。指摘は「画素の位置 + 参考画像では何 + 描画では何」で具体的に（[reference/checklist.md](reference/checklist.md) の「見直しの表」）
4. 2 回戻しても数値も絵も動かなければ、指摘をまとめて新しい担当に引き継ぐ

## 決めごと

- **参考画像の画素を自動で場面へ写さない**（カメラマッピング禁止）。手で測った値を書くのは可
- **自動の値探しで形・明暗の構造を潰さない**（色の微調整だけに使う）
- ノイズはワールド座標、影のカメラは固定（歩いても泳がない・段が動かない）
- 撮影画像は `scratch/`（git 管理外）。コミットしない
