| 起きたこと | 原因 | 対策 |
|---|---|---|
| 淡色の廊下の最初の版が ΔE 7.1 | 画角を推測（62°）で始めた。解き直すと 44.4° | 段階 4-1 で消失点と既知の寸法からカメラを解く（`solveFromVanishingPoint`） |

| 自動の値探しで ΔE は下がったが明暗が平らに | ΔE は「平らにすると下がる」ことがある | 自動調整は色の微調整だけ。必ず `-cmp.png` を目で見る |
| 3 つの担当が画素 ↔ 座標の道具を別々に書いた | 道具が無かった | `src/core/ViewCam.ts` |
| 「影の升目」が効いていなかった | three の `#include` は onBeforeCompile の後で展開されるので、include の中身の置き換えが空振り | 置き換える前に `THREE.ShaderChunk` の中身を展開して置き換える。置き換えが見つからなければ例外を投げる。確認の場面で撮る |
| 法線の線が点線になった | MSAA で縁の画素の法線が平均される。中心と比べるとしきい値をまたいで点滅 | 向かい合う 2 画素の組で比べる（入れ済み） |
| 駅の水たまりの形が参考画像から自動で焼かれていた | 担当への指示に禁止を書いていなかった | 指示の最初に「参考画像を読み込んで写さない」を書く。`grep -rn "refs/\|\.jpg\|base64" src/scenes` で確かめる |
| 屋根の下の霧の箱の縁が半透明の箱に見えた | 体積の縁が硬い。参考画像の視点からは見えない | 体積の効果は縁を 1〜2 m でぼかす。視点の間を歩いて撮る |
| 草の細い縦線が雨・バーコードに見えた | 模様の大きさが画素に近い | 0.2〜0.5 m の柔らかい塊にする。遠くでは模様を消す |
| 椅子が黒い板の塊に見えた | 背もたれを 1 枚の板にした | 1 席ずつの座面と背・隙間・細い脚まで作る |

| 担当の改善が 2 回目以降で鈍った | 文脈が長くなり、同じ方針に固執 | 2 回戻しても動かなければ、指摘をまとめて新しい担当へ |
| 開発サーバーが止まっていた | アプリが時間で止める | `npm run dev --prefix experiments/visual-style-lab` か preview_start で起動し直す |

## 建築版（2026-10-07 同じ 14 枚を間取り図から作り直した）

| 起きたこと | 原因 | 対策 |
|---|---|---|
| 参考画像の視点のために描いた影が、別の角度から変な形に見えた | 影の形を視点の画面で決めていた | 視点の近くで同じ向きを見ているときだけ出す。日なたの形は壁の座標の絵で決める（どこから見ても同じ所が明るい） |
| 区画が多い建物で描く物が増えて重くなりかけた | 見えない部屋まで描いていた | 扉・開口でつながった区画だけ描く（見通しのある所から）。動かない場面は `staticShadows` |
| 写っていない部屋の扉を、視点の見た目を変えずにどこへ置くか迷った | — | `ViewCam` で柱型・枠の陰（目から見えない範囲）を求め、そこに扉を置く（淡色の廊下は元の版との違い 0.02 % の画素） |
| 歩いて届くかの確かめで、深い水も「歩ける床」になっていた | 水の中の当たり判定は遅い床（水深は持っていなかった） | `Box.depth` に水深を入れる。`--reach` は水深 1.2 m より深い水を通らないと行けない所を「泳げば届く」と出す（視点は泳がずに届くこと） |
| 道順の重さの測定（`--tour --perf`）が途中で落ちた | 測定中に Vite がページを読み直した | `evaluate` が理由を出して、場面を開き直して 1 回やり直す（入れ済み） |

## 2 つ目の参考画像の組（2026-10-11 imageboart_20261008 の 6 か所・17 視点を並行の担当で）

| 起きたこと | 原因 | 対策 |
|---|---|---|
| 1 つのフォルダに別の場所の画像が入っていた（pools = ウォーターパークと教室、whiteroom = 中庭と立方体の大広間） | フォルダ名と場所が 1 対 1 ではない | ファイル名の生成の指示文（先頭の英文）で組に分け、組ごとに 1 つのステージにする。報告にフォルダとの対応を書く |
| 4:3 の参考画像（1232×928）で、間取り図の画角の扇が 16:9 のまま | 図の扇の横の画角が 1456 / 816 で決め打ち | ViewDef に `size: [w, h]` を書く。撮影・比べ・扇はその比率になる（入れ済み） |
| ウォーターパークの ΔE が 2 回直しても 11〜12 から下がらない | 明るさの差 ΔL 1・彩度の差 0.2 で色はほぼ合っている。描き込みの細かい参考画像では、画素ごとの差（細部・物の位置）が ΔE の大半になる | ΔE が大きいときは先に `metrics.json` の ΔL・彩度・地域ΔE を見る。色が合っていれば色調整で追わない（平らになる）。形と明暗の部位で詰め、2 回で頭打ちなら差を書いて受け入れる |
| 質感の物差しの比が、細部を全体に足しても動かない（立方体の大広間 0.66〜0.85） | 比は「視点の描画」に対する値。全体に掛ける決まりは視点の描画も同じだけ上げる | 比を上げるのは、写っていない所にだけ欠けている中くらいの形（開口・庇・設備・段差）。面の模様を足しても比は動かない |
| 部屋の灯りの丸い縁が壁を横切った | 灯りに `hard` を付け、照らす箱を部屋より大きく取った | 丸い灯りは柔らかい減衰で、照らす箱を部屋の内側に切る。`hard` は四角い窓・日なたの形だけ |
| 同じ面に重なった違う材質の箱が、Apple の GPU で 32 画素の黒い升目になった | 同じ平面の 2 枚の面（z-fighting） | 形を離す（1 cm でも）。念のため材質ごとに `polygonOffset` |
| 24 m より遠い光だまりが視点から消えた | `LampSet.maxDist` が 24 m 固定 | 広い場面は `ctx.setLampRange(m)` で伸ばす（入れ済み） |
| 水面の映り込みが白黒の縞になった | 手すりの映り込みに細かいゆがみ（distort）を強く掛けた | 細い物が映る水面は distort を小さく、縦にならす |
| 重さの測定の前に、担当の止まった撮影（1 時間）と自前の撮影用の Chrome が残っていた | 担当の作業が止まったまま終わった | 最終の重さを測る前に `pgrep -fl headless` で残りを確かめて止める。Browser の窓も閉じる |
| 元の版の `all` に建築版だけの参考画像が入って、無い場面を撮っていた | `all` は public/refs の全部 | 撮影の道具が、ページに無い場面を飛ばす（入れ済み） |
| ウォーターパークの滑り台を、1 つの部品の中にミントのまだら（blotch）を塗った桃色で作り、利用者に「元画像は接続される部品ごとに色が決まっている（桃色と水色の部品をつないでいく作り）」と指摘された | 参考画像の色の分かれ方を「模様」と読み、作りの理屈（成形の部品・継ぎ目）を読まなかった | **色と模様は作りに従う**: 物の色は部品・板・区画・タイルごとに決まり、色の境目は継ぎ目・つば・目地にある。参考画像の色の境目が何の境目かを先に言語化する（段階 0）。面の上にまだら・迷彩・無作為の四角を塗って細部の代わりにしない（汚れも水の流れ・目地の下など作りに沿わせる） |
| 質感の物差しの比が、視点 2・4 枚の場所で低く出た | 偶数個の中央値で大きい方を取っていた | 真ん中の 2 つの平均に直した（`capture.mjs`。入れ済み） |
| 床の光だまりを足し算の板で置いたら、廊下に同じ楕円が並んで「シール」に見えた | 縁の硬い板・同じ形の繰り返し・遠くまで同じ明るさ | 中心から 0 まで滑らかに落とす（平らな所を作らない）・器具の真下だけ・区域ごとに形を変える・遠くで薄くする |
| ウォーターパークは 2 回直しても動かなかったが、新しい担当へ指摘をまとめて渡すと構図 F が +1〜+9.5、写っていない所の印が 11/18 → 3/18 | 同じ担当は自分の作りの前提に固執する | 2 回で頭打ちなら、指摘と数値と「何が足りないか」をまとめて新しい担当へ（前の表の対策がここでも効いた） |
